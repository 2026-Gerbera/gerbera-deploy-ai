# 클라우드 HTTPS: 관리 페이지 도메인 방식 검증 (2026-09-30)

> 검증 에이전트 3개(acm · alb · pipeline)의 결과를 합친 문서입니다. 공식 문서(AWS, Terraform, Python, PostgreSQL)를 근거로 했습니다.
> 판정 표기: **확인** / **일부 확인** / **반박** / **미확인**(문서로 확인할 대상이 아닌 설계 판단 포함). 확인하지 못한 것은 "확인 필요"로 적었습니다.

## 1. 결론 (3줄)

1. 관리 페이지에 적은 도메인 하나로 파이프라인이 ACM 발급·검증, ALB 443 연결, 80→443(301) 전환, DNS 레코드까지 처리할 수 있습니다. 단, **도메인 DNS가 같은 계정의 Route 53 공인 호스팅 영역일 때만 완전 자동**입니다. DNS가 외부에 있으면 사람이 CNAME을 넣어야 합니다.
2. ACM 신규 발급에는 SLA가 없습니다(레코드 생성 후 최대 30분, 발급까지 수 시간 가능). **3분 데모 안에서 새로 발급하면 안 됩니다.** 같은 `ensure_tls`를 도메인 저장 직후 한 번 돌려 미리 발급하고, 데모 때는 기존 인증서를 재사용하는 경로만 탑니다(수 초 예상, 실측 필요).
3. boto3·Terraform으로 만든 리스너의 기본 보안 정책은 `ELBSecurityPolicy-2016-08`(TLS 1.0 허용, TLS 1.3 없음)입니다. **`ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09`를 반드시 명시**합니다. RDS Postgres 15 이상은 SSL 강제가 기본이므로 클라이언트를 `sslmode=verify-full`로 맞춥니다.

## 2. 사용자 결정 요약 (정준우, 2026-09-30, 최종)

| 항목 | 결정 |
|---|---|
| 클라우드 HTTPS | 반드시 배포까지 되게 한다. 작년(2025) 수상작도 HTTPS까지 배포했다(사용자 확인) |
| 클라우드 도메인 | **사람이 관리 페이지에 입력**한다. 관리 페이지 백엔드(실행기 쪽 프로젝트 설정 저장소)에 저장되고, 실행 때 실행 컨텍스트로 툴에 전달된다. `deploy.yaml`에 적지 않는다 |

## 4. 권장 구성

### 4-1. 관리 페이지 입력 항목

| 항목 | 키 | 필수 | 값 예시 | 설명 |
|---|---|---|---|---|
| 클라우드 도메인 | `cloud_domain` | 예 | `app.<팀 도메인>` | 앱을 서빙할 FQDN 하나. 소문자, 끝 점 없음 |
| DNS 방식 | `dns_mode` | 예 | `route53` / `external` | 같은 계정 Route 53 공인 영역이면 `route53`(완전 자동). 아니면 `external`(사람이 CNAME 추가) |
| 호스팅 영역 ID | `hosted_zone_id` | `route53`일 때 | `Z0123...` | 비우면 저장 때 `ListHostedZonesByName`으로 가장 긴 접미사 영역을 찾아 채우고 사람이 확인 |
| (선택) 와일드카드 | `wildcard` | 아니오 | 끔 | 켜면 `*.<부모>` + `<부모>` 인증서. 앱 이름을 바꿔도 재검증 없음. 기본은 FQDN 한 장 |

### 4-2. 저장 위치와 전달 방식

| 단계 | 내용 |
|---|---|
| 저장 | 관리 페이지 백엔드의 **프로젝트 설정 저장소**(실행기 쪽). 필드: 위 4개 + `version`, `updated_by`, `updated_at`. 저장 형식(DB 테이블/파일)은 팀 결정, 확인 필요 |
| 쓰기 권한 | 관리자 인증 경로(관리 페이지 설정 화면)만. AI 서비스 계정·계획 실행 경로에는 쓰기 권한 없음. 변경 이력 남김 |
| 스냅샷 | 실행기가 실행 시작 때 설정을 읽어 실행 레코드에 고정(`cloud_domain` + `version`). 실행 중 설정이 바뀌어도 그 실행은 스냅샷 값 사용 |
| 주입 | 실행 컨텍스트 `cloud_domain`, `dns_mode`, `hosted_zone_id`로 클라우드 툴(`ensure_tls`, `verify_tls`, `health_check`, `smoke_test`, `compare_env_results`)에 전달 |
| AI 차단 | 툴 파라미터 스키마에 domain 필드 없음(`additionalProperties: false`). 계획 검증이 `domain`·`host`·`url`·`zone`·`hosted_zone*` 키를 불합격 처리. AI는 결과 보고용으로 값을 읽기만 함 |
| 최후 방어 | IAM: Route 53 쓰기는 허용된 영역 ARN만, `acm:ValidationMethod=DNS`, `acm:DomainNames`는 허용 영역 이름 패턴만 |
| 쓰지 않는 곳 | `deploy.yaml`, Terraform 변수, 계획 JSON에는 도메인을 적지 않는다 |

> 인프라 값(ALB ARN, 대상 그룹 ARN, 80 리스너 ARN, 허용 호스팅 영역 ID 목록)은 Terraform 출력에서 실행 컨텍스트로 들어옵니다. 허용 영역 목록은 IAM 범위를 정하는 인프라 경계이고, 도메인 값 자체는 아닙니다.

### 4-3. 인증서 사전 발급

| 항목 | 권장 |
|---|---|
| 방식 | 관리 페이지 "도메인 연결" 버튼 → 실행기가 AI 없이 `[ensure_tls(cloud), verify_tls(cloud)]` 두 단계 계획만 실행. 같은 툴을 데모 run에서도 씀 |
| 시점 | 도메인 저장 직후. 늦어도 데모 전날(10/2) 리허설 전 ISSUED |
| 인증서 | ACM, ap-northeast-2, DNS 검증, RSA_2048, 태그 `managed-by=pipeline`, `project=<이름>` |
| 이름 | 기본: `cloud_domain` 한 장. 와일드카드 옵션: `*.<부모>` + `<부모>`(검증 CNAME 1개로 둘 다 검증) |
| 데모 run | 기존 ISSUED 재사용 경로만 탐(수 초, 실측 필요). 발급이 필요한 상황이면 대기 상한(제안 60초) 후 실패하고 "관리 페이지에서 도메인 연결 필요" 표시 |
| 도메인 변경 | 재발급이 필요하므로 마감(10/2) 이후 변경 금지. 관리 페이지에 경고 표시 |
| 정리 | teardown에서 검증 CNAME과 사용 중 인증서는 지우지 않는다(지우면 자동 갱신이 멈추고 재발급 대기 발생) |

### 4-4. ALB 443 · 보안 정책 · 80→443

| 항목 | 값 | 누가 |
|---|---|---|
| ALB·대상 그룹 | ALB, 대상 그룹 HTTP·대상 유형 ip(Fargate) | Terraform(C1) |
| 보안 그룹 | 인바운드 80·443 공개(443 리스너가 생기기 전부터 열어 둠) | Terraform(C1) |
| 80 리스너 초기값 | 대상 그룹으로 forward(도메인 연결 전 디버깅용). Terraform에서 `lifecycle { ignore_changes = [default_action] }` | Terraform(C1) |
| 443 리스너 | HTTPS, 기본 인증서 1장, forward → 대상 그룹 | `ensure_tls`(cloud) |
| 보안 정책 | **`ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09`** 명시(호환 문제 시 대안 `ELBSecurityPolicy-TLS13-1-2-2021-06`) | `ensure_tls`(cloud) |
| 80 리스너 최종값 | redirect → HTTPS:443, `HTTP_301`, host·path·query 유지. 443이 생긴 뒤에 전환 | `ensure_tls`(cloud) |
| HSTS | 443 리스너 속성 `max-age=300`(데모용으로 짧게, `includeSubDomains`·`preload` 제외). 80에는 걸지 않음 | `ensure_tls`(cloud) |

> 443 리스너는 인증서 없이 만들 수 없고, 도메인은 Terraform에 없으므로 443은 `ensure_tls`가 만듭니다. 이 때문에 Terraform과 파이프라인이 리스너를 나눠 가집니다. Terraform이 80 리스너의 default_action을 되돌리지 않도록 `ignore_changes`가 필요합니다(설계 판단).

### 4-5. DNS 레코드

| DNS 방식 | 검증 CNAME | 서비스 레코드 | 누가 |
|---|---|---|---|
| `route53` | `ensure_tls`가 UPSERT(TTL 60) → GetChange INSYNC | A 별칭 → ALB(ALB가 dualstack이면 AAAA도). apex 가능 | 자동 |
| `external` | 관리 페이지에 Name·Value 표시 → 사람이 추가 → 승인 | CNAME `cloud_domain` → ALB DNS 이름. **apex 불가**(서브도메인 필수) | 사람 |
| 외부 도메인 + 서브도메인 위임 | Route 53에 서브 영역 생성 후 부모 DNS에 NS 4개 추가(사람 1회) → 이후 `route53`과 같음 | 같음 | 1회 사람, 이후 자동 |

## 5. `ensure_tls`(cloud) 단계별 동작

모든 단계는 **조회 후 필요한 것만 변경**합니다. 재실행해도 결과가 같습니다(멱등).

| # | 동작 | boto3 API | 실패 조건 |
|---|---|---|---|
| 0 | 입력 점검: `cloud_domain` 형식, `dns_mode`. route53이면 영역이 공인인지(PrivateZone=false), 도메인이 영역 이름으로 끝나는지 | `route53.get_hosted_zone` | 형식 오류, private 영역, 접미사 불일치 |

| 5 | 검증 CNAME 반영. route53: UPSERT(TTL 60) 후 INSYNC 대기(5초 간격, 최대 120초). external: 진행 이벤트로 Name·Value 전달 + `request_approval` | `route53.change_resource_record_sets`, `get_change` | INSYNC 시간 초과 |

## 6. `verify_tls`(cloud) 검사 항목과 합격 기준

TLS 검사는 ALB DNS 이름에 **SNI=`cloud_domain`**으로 연결해 DNS와 분리합니다. DNS는 따로 봅니다. 결과는 pass / fail / inconclusive 3상태입니다.

| # | 검사 | 방법 | 합격 기준 | 필수 |
|---|---|---|---|---|
| V1 | DNS 연결 | `getaddrinfo(cloud_domain)` ∩ `getaddrinfo(ALB DNSName)`. route53이면 `ListResourceRecordSets`로 별칭 대상도 확인 | 교집합 있음(ALB IP는 바뀔 수 있어 교집합으로 판단) | 예 |
| V2 | 핸드셰이크·체인·호스트명 | `ssl.create_default_context()`로 연결 | 검증 오류 없음 | 예 |
| V3 | 협상 버전 | `SSLSocket.version()` | TLSv1.2 이상. 정책상 TLSv1.3 기대(표시) | 예 |
| V4 | 인증서 내용 | `getpeercert()`: issuer O, notAfter | O=Amazon, 남은 일수 30일 이상 | 예 |
| V5 | ACM 교차 확인 | `describe_certificate` | Status=ISSUED, InUseBy에 ALB ARN, NotAfter가 V4와 일치 | 예 |
| V6 | 리스너 설정 | `describe_listeners` | 443 SslPolicy = 허용 목록 값, 80 기본 동작 = redirect HTTPS:443 HTTP_301 | 예 |
| V7 | http 리다이렉트 | `http.client`로 `http://cloud_domain/` | 301, Location이 `https://cloud_domain/`으로 시작 | 예 |
| V8 | TLS 1.0/1.1 거부 | `SECLEVEL=0`, min=max=TLSv1(또는 TLSv1_1), 인증서 검증 끔. 먼저 `ssl.HAS_TLSv1` 확인 | 서버 alert `TLSV1_ALERT_PROTOCOL_VERSION`이면 pass. `NO_CIPHERS_AVAILABLE`·`NO_PROTOCOLS_AVAILABLE`·`UNSUPPORTED_PROTOCOL`은 inconclusive | 아니오 |
| V9 | HSTS | 앱 200 응답(예: `/health`)의 `Strict-Transport-Security` | 헤더 있음(ALB 자체 응답은 확인 필요라 앱 응답으로 검사) | 아니오 |

- 전체 합격: V1~V7 모두 pass. V8·V9는 결과 카드에 표시만 하고 불합격 사유로 쓰지 않습니다.
- 로컬: 어댑터가 "보류(해당 없음)"를 반환합니다. 교차 비교 대상이 아닙니다.
- 필요 권한(읽기만): `acm:DescribeCertificate`, `elasticloadbalancing:Describe*`, `route53:ListResourceRecordSets`. 실행기에서 공인 인터넷 80·443으로 나갈 수 있어야 합니다.
- 결과 카드 문구 예: `https://<도메인>` · 발급자 Amazon · 남은 일수(10/1 발급이면 데모 때 약 195일, 추정) · TLS 1.3 · HTTP→301 · TLS 1.0/1.1 서버 거부.

|---|---|
| 설정: 도메인 입력 | 도메인 입력칸, DNS 방식(Route 53 / 외부 DNS), 호스팅 영역 ID(자동 찾기 버튼), 와일드카드 옵션, 저장 버튼, "도메인 연결" 버튼 |
| 저장 시 형식 검증 | 소문자 변환, 끝 점 제거, `https://`·포트·경로·IP·와일드카드 입력 거부, ACM 정규식, 전체 253자·라벨 63자·64자 이하, 한글 도메인은 punycode 변환, `amazonaws.com`·`cloudfront.net`·`elasticbeanstalk.com` 거부, route53이면 영역 이름 접미사 확인, external이면 "apex 불가, 서브도메인 입력" 안내 |
| 검증 CNAME 안내(external) | Name·Value 복사 버튼, 서비스 CNAME(`cloud_domain` → ALB DNS 이름), 주의 문구(이름칸에 도메인 자동 부착 업체, 끝 점, 밑줄), "추가 완료" 승인 버튼, 72시간 제한 표시 |
| 인증서 상태 | 없음 / 요청됨 / 검증 대기(경과 시간) / 발급됨(만료일·남은 일수) / 사용 중(ALB 연결) / 실패(FailureReason). 실행기 API가 `ensure_tls` 결과와 `DescribeCertificate`(읽기)로 제공 |
| 변경 경고 | 도메인 변경 시 재발급 필요(최대 30분 이상). 데모 마감 이후 변경 잠금(선택) |
| 결과 카드 | 로컬 `http://localhost:8080`(HTTPS 보류 라벨), 클라우드 `https://<도메인>`, 6절의 TLS 결과 |

## 8. 앱 패치 영향 (`patch_config`, 토글 ON일 때)

| 항목 | 증상 | 조치 | 환경 |
|---|---|---|---|
| X-Forwarded-Proto | 리다이렉트·링크가 `http://`로 생성 | ProxyFix(`x_for=1, x_proto=1, x_port=1`, `x_host=0`). 실제 프록시 홉 수만큼만 신뢰 | 클라우드만(환경 플래그). 로컬에서 켜면 헤더 스푸핑 허용 |
| web tier nginx | nginx가 `X-Forwarded-Proto $scheme`으로 덮어 WAS가 http로 인식 | ALB가 준 값을 그대로 전달하도록 설정. ALB→nginx→WAS 구성이면 신뢰 홉 수 재확인(확인 필요) | 클라우드 |
| `http://` 하드코딩 | HTTPS 화면에서 API 호출 차단(mixed content) | 상대 경로 `/api` 또는 실행 시 설정 | 두 환경 |
| 쿠키 `Secure` | 세션 쿠키 평문 전송 가능 | `SESSION_COOKIE_SECURE`(와 HttpOnly)를 환경 플래그로 | 클라우드 ON, 로컬 OFF |
| HSTS 위치 | – | 앱이 아니라 ALB 443 리스너 속성. 앱 코드 수정 없음 | 클라우드 |

- 교차 검증에서 스킴(`http`/`https`), `Secure` 쿠키, HSTS 헤더, 301 동작은 **예상된 차이**로 비교에서 제외합니다.

## 9. RDS TLS

| 항목 | 권장 |
|---|---|
| 엔진 | Postgres 15 이상이면 `rds.force_ssl=1`이 기본. 파라미터 그룹 변경 불필요 |
| 클라이언트 | 클라우드 `DATABASE_URL`에 `sslmode=verify-full&sslrootcert=/app/certs/global-bundle.pem`. RDS 엔드포인트 호스트명으로 접속(IP·별칭 CNAME이면 호스트명 검증 실패) |
| CA 번들 | CodeBuild 단계에서 truststore URL로 받아 이미지에 포함(또는 저장소에 고정 파일 + 체크섬). 루트 CA만 넣음 |
| 마이그레이션 | `prepare_db`의 일회성 태스크도 같은 `sslmode` 사용 |
| 로컬 | Docker Postgres는 보통 SSL 없음 → 로컬 `DATABASE_URL`은 SSL 옵션 없음. 교차 검증에서 예상된 차이로 명시 |
| MySQL을 고르면 | `require_secure_transport=ON`을 명시(RDS 기본 OFF) |

## 10. 로컬 HTTPS 보류 이유

| 이유 | 설명 |
|---|---|
| 사용자 결정 | 퍼블릭 IP가 필요한지 아직 모름. 로컬은 `http://localhost:8080` |
| 로컬 CA(mkcert 등) | 데모 노트북에서만 신뢰됨. "누구나 접근" 조건을 채우지 못함 |
| 공인 인증서 | 로컬 서버가 쓸 공인 도메인·DNS가 필요. ACM ACME는 CNAME 사전 검증만으로 받을 가능성이 있으나 퍼블릭 IP·비용은 확인 필요 |
| 파이프라인 처리 | `ensure_tls`·`verify_tls` 로컬 어댑터는 "보류(해당 없음)" 반환. 툴 수 33개 유지 |

## 12. 남은 불확실성

| 항목 | 상태 |
|---|---|
| 데모 도메인을 누가 제공하는가(DNS 수정 권한 포함) | 확인 필요(팀 결정) |
| 실제 발급 소요 시간 | 실측 필요(문서상 SLA 없음) |
| 데모 run의 `ensure_tls` 재사용 경로 소요 시간 | 실측 필요(수 초 추정) |
| PENDING_VALIDATION 인증서를 리스너에 붙일 수 없다는 점 | 공식 문서 명시 없음(re:Post만). ISSUED 후에만 연결하므로 영향 없음 |
| 리스너 인증서 교체 반영 시간 | 확인 필요. 데모 전에 연결해 둠 |
| ALB 자체 응답(리다이렉트·5xx)에 HSTS가 붙는지 | 확인 필요. HSTS 검사는 앱 200 응답으로 |
| `CreateListener`의 `ListenerProtocol`·`SecurityPolicy` 조건 키 지원 | 확인 필요 |
| RequestCertificate에 Tags를 줄 때 `acm:AddTagsToCertificate` 권한 필요 여부 | 확인 필요 |
| SearchCertificates의 와일드카드 매칭 | 확인 필요(쓰지 않으면 무관) |
| 가비아·Cloudflare 등 외부 DNS 화면 동작, CNAME flattening | 확인 필요 |
| RDS for MySQL 8.4의 `require_secure_transport` 기본값 | 확인 필요(Postgres면 무관) |
| 실행기 이미지 CA 번들 | 확인 필요 |
| Terraform과 `ensure_tls`의 리스너 소유 분담(드리프트) | 설계 판단. `ignore_changes`로 처리, 실제 apply로 확인 필요 |

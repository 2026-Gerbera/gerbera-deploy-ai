# 21. 트리거 개편 — 문서 수정 목록 (10/1 저녁)

> **📌 10/1 밤 회의:** 브랜치 이름 `prod`(개발자) → `ai-prod`(후보) → `main`(배포된 코드), 환경별 기록은 태그 `deployed/onprem`·`deployed/cloud`. 온프렘·클라우드 대기 지점 제거(독립 진행, 교차 검증은 둘 다 성공 시).

> 기준: [20 트리거 개편](20_트리거-개편-git-브랜치-기준.md)(✅ 정준우, 10/1 저녁). 표기: ✅ 확정 / 🟡 합의 대기 / 💭 고려안 / ⏸ 보류.
> 원칙: 최소 수정. 각 문서 맨 위에 📌 한 줄을 달고, 계약 문서(01)의 핵심 충돌 문장만 그 자리에서 고쳤습니다. 코드는 바꾸지 않았습니다.
> 경로 `dev-docs/` = `single-app/dev-docs/`.

## 한눈에

제품은 `validate_infra` → `plan_infra` → 한 화면의 infra 승인 → foundation(state bucket + app/build 권한 경계) → platform apply 순서로 실행합니다. bucket이 없으면 local backend plan을 승인한 뒤 코드가 SDK로 bucket을 만들고 platform local apply 후 remote backend로 state를 이전합니다. 사람이 미리 foundation/platform을 apply하는 전제는 폐기합니다. 사람의 사전 준비는 AWS 자격증명과 도메인 구매입니다. AI 개발 에이전트는 Terraform을 직접 실행하지 않으며, 승인 뒤 제품 코드가 실행하는 경로와 구분합니다. 실제 생성기의 O2 연결은 아직 미완이고 AWS 전체 완료를 의미하지 않습니다.

💭 v2 기능은 미정이며 로그인은 후보입니다. 정준우의 10/2 검증은 1차 Flask 기본 앱에 이미지·박스를 추가한 파이프라인 E2E, 2차 실제 로직의 LLM 분석·패치·인프라 생성 검증으로 나눕니다. 1차 결과로 실제 LLM·AWS 전체 완료를 주장하지 않습니다.

앱 저장소의 dev 단일 브랜치·옛 README 상태는 사용자 전달 기준(실시간 미조회)입니다. prod·ai-prod·main 생성과 기본 prod 전환, prod/* ref 충돌 처리 가이드는 [docs/20](20_트리거-개편-git-브랜치-기준.md#앱-저장소-전환-가이드-실제-git-조작-없음)를 따릅니다.

| 바뀐 것 | 이전 | 이후 |
|---|---|---|
| 입력 | 개발자 PC 로컬 폴더 스냅샷 | GitHub 저장소 + 브랜치(기본 prod, 10/1 밤에 dev에서 이름 변경), 공개 저장소 |
| 시작 | 채팅 지시 | ① 수동 채팅 지시 ② prod 새 커밋 자동 감지(10~30초 폴링). 승인은 그대로 |
| 변경 탐지 기준 | 환경별 마지막 성공 스냅샷 해시 목록 | 새 prod 커밋 ↔ 환경별 마지막 성공 `source_sha`(그때 쓴 prod 커밋). 태그 `deployed/<환경>`·이미지 라벨은 `candidate_sha`(실제로 도는 ai-prod 커밋) |
| 패치 적용 | 빌드용 스냅샷에 적용 | ai-prod에서 승인 트리를 고정한 merge 커밋 하나를 일반 push(이력 보존). 실행기(정준우)가 함 |
| 빌드 소스 | 승인 뒤 수정본 스냅샷 → S3 | 후보 커밋(ai-prod HEAD), 이미지 라벨에 커밋 SHA. S3는 필요할 때만(확인 필요) |
| 배포 대상 | 항상 둘 다, cloud 단독 거부 | run마다 온프렘만 / 클라우드만 / 둘 다 |
| 대기·교차 검증 | 항상 | 대기 지점 없음(✅ 10/1 밤 분리). 교차 검증은 둘 다 성공했을 때만 |
| 릴리스 기록 | 원본·수정본 스냅샷 해시(git SHA 참고) | `source_sha`(prod 커밋)·`candidate_sha`(후보 커밋) 둘 다 필수 |

## 5. 참고

- 현행 ai-prod는 prod와 기존 ai-prod 이력을 보존하면서 **merge 커밋 하나의 관리 트리를 승인 build_files로 고정**하고 일반 push합니다. 별도 새 패치 커밋을 얹는 설명은 대체되었습니다.
- 새 패치가 없어도 후보 관리 트리는 승인 build_files와 일치해야 합니다. 패치 OFF면 prod 원본이 승인 트리여서 이전 AI 패치가 빠집니다(**정준우 확인 대기**). 최초 동일 부모인 경우 커밋 부모는 하나일 수 있습니다.

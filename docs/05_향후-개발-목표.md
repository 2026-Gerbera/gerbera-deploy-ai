# 05. 향후 개발 목표 (⏸ 보류 항목)

> 2026-09-29 결정: 보안 도구(SAST·DAST·SCA 등)는 이번 해커톤의 핵심이 아니므로 **추후 개발 목표로만 기록하고 이번 범위에서 뺍니다.**
> 설계 문서의 "검토했지만 제외한 대안"으로도 쓸 수 있습니다(팀 개발 20점).

## 1. 보안 컴포넌트

아래 배치 위치와 시간은 조사 기반 참고치(추정)입니다. 도입할 때 실측해야 합니다.

| 컴포넌트 | 하는 일 | 실무의 보통 배치 | 실행 시간 참고(추정) | 비고 |
|---|---|---|---|---|
| 시크릿 탐지 | 커밋·설정·이미지에 들어간 키·토큰 유출 탐지 | 커밋 전 훅 + PR/push 시점 | 수 초~수십 초 | 소규모 팀이 가장 먼저 넣으라고 흔히 권하는 항목 |
| SAST | 소스코드의 취약 패턴 정적 분석 | PR 시점(변경분만) + main 전체 스캔 | 도구에 따라 수 초~수 분 | |
| SCA | 서드파티 패키지의 알려진 CVE·라이선스 위반 탐지 | PR 시점 + main 빌드 + 지속 모니터링 | 수 초~1분 | 시크릿 탐지와 함께 우선순위 높음 |
| IaC 스캔 | Terraform·Dockerfile 등의 잘못된 설정 탐지 | 인프라 코드 PR 시점 또는 적용 직전 | 수 초~수십 초 | |
| 컨테이너 이미지 스캔 | 이미지의 OS·언어 패키지 CVE 탐지 | 이미지 빌드 직후, 저장·배포 전 | 수십 초 (취약점 DB 다운로드·캐시에 좌우) | 샘플 앱에 이미 High/Critical 취약점이 있으면 차단 게이트가 데모를 막을 수 있음 |
| SBOM 생성 | 아티팩트 구성요소 목록화 | 빌드 직후 | 수 초 | |
| 서명·프로비넌스 | 아티팩트 무결성·출처 증명, 배포 시 검증 | 빌드·저장 직후 서명, 배포 직전 검증 | 수 초 | 클라우드별 검증 기능이 달라 "클라우드 특유 기능" 소재가 될 수 있음 |
| 정책 게이트 | 스캔 결과·인프라 계획에 규칙을 적용해 통과/차단 결정 | 스캔 후 배포 직전 | 수 초 | |
| DAST | 실행 중인 앱에 HTTP로 접근해 런타임 취약점 탐지 | **배포 후 임시·스테이징 환경** 또는 야간 스케줄. 운영 대상 공격형 스캔은 금지 권고(GitLab) | ZAP 기본 스캔: 스파이더 최대 1분(공식) + 분석 대기 + 약 1.2GB 이미지. 이미지를 미리 받아 두면 60~120초, 아니면 2~4분(추정) | **3분 데모에 차단 단계로 넣으면 불가(추정).** 비동기 실행이나 이전 결과 표시만 현실적. 배포 방식에 따라 배치가 달라짐 |
| 런타임 보안 | 실행 중 이상 행위 탐지 | 파이프라인 밖에서 상시 | – | |

**나중에 도입할 때 참고할 점:**
- 정적 스캔(시크릿·SAST·SCA·IaC)은 빌드와 병렬로 돌리면 3분 데모의 핵심 경로에 거의 더해지지 않습니다(+0~30초, 추정). 이미지 스캔·SBOM·서명까지 더하면 배포 시간이 30초대여야 3분에 들어갑니다(추정).
- **대부분의 스캐너 게이트는 기본값이 "실패하지 않음"입니다.** 막는 장면을 보여주려면 실패 옵션을 명시해야 하고, 반대로 일부 도구는 기본값이 중간 등급부터 차단이라 예상 못 한 차단이 날 수 있습니다.
- AI로 스캔 결과를 거르고 수정 PR을 만드는 기능은 이미 여러 제품이 제공합니다(GitHub Copilot Autofix, Semgrep, Snyk 등). 차별 여지는 "스캔 결과를 배포 결정과 근거 로그로 연결하는 방식" 정도입니다.
- 스캐너를 한꺼번에 넣으면 파이프라인이 느려지고 경보 피로가 생긴다는 것이 일반론입니다. 흔한 권고 순서는 시크릿 탐지·SCA → SAST → 이미지 스캔 → IaC 스캔입니다.
- 결과가 너무 많으면 게이트가 배포를 막고, 너무 없으면 보여줄 게 없습니다. 차단 기준(예: Critical만 차단)을 먼저 정해야 합니다.

## 2. 도구가 아닌 기본 설정 (참고)

보안 "도구"는 아니지만 적은 비용으로 할 수 있는 파이프라인 기본 설정입니다. 넣을지 말지는 세부 디테일 단계에서 판단합니다.
- 클라우드 인증은 장기 액세스 키 대신 단기 토큰(OIDC 등)으로
- 파이프라인 권한 최소화
- 외부 액션·플러그인 버전을 커밋 해시로 고정

**근거 사례 (검증 완료):** 2026-03-19~20 약 12시간 동안 보안 스캐너 Trivy의 GitHub Action(`aquasecurity/trivy-action`) 태그 77개 중 76개가 악성 커밋으로 강제 교체됐습니다. 호스티드 러너에서는 메모리 덤프로 시크릿을, 셀프호스티드 러너에서는 파일시스템에서 클라우드 자격증명과 K8s 토큰을 탈취했습니다([GHSA-69fq-xp46-6x23](https://github.com/aquasecurity/trivy/security/advisories/GHSA-69fq-xp46-6x23), CVE-2026-33634). 1만 개 이상의 워크플로 파일이 이 액션을 참조하고 있었습니다(Socket 집계). 2026-03~04에는 Checkmarx KICS의 Action·이미지도 침해됐습니다. → **"보안 스캐너를 넣는 것 자체도 공급망 위험"**이라는 점을 설계문서의 대안 논의 소재로 쓸 수 있습니다.

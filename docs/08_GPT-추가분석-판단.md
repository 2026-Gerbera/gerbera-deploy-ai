## 2. 얻어갈 것 (우리 계획에 반영할 것)

1. **"누른 뒤 실제 배포까지 끝까지 닫힌 흐름"이 1순위입니다.** 탈락팀 블로그, Yoitang의 "끝까지 만든 완성도" 심사평, Orange의 E2E가 같은 방향을 가리킵니다. 기능 여러 개를 70%로 만드는 것보다 핵심 흐름 하나를 100%로 만드는 게 낫습니다.
2. **데모 스택은 일찍 확정하고 단순하게 가져갑니다.** Orange는 발표 이틀 전에 복잡한 관리형 Blue/Green을 접고 단순한 구성으로 바꿨습니다. 우리 기준으로는 개발 2일차까지 데모 경로를 고정하는 것이 목표입니다.
3. **데모 대본을 먼저 씁니다.** Orange 대본의 구조를 3분에 맞게 줄여 쓸 수 있습니다:
   - 사전 준비
   - 상황 선언(30초)
   - 준비 상태 확인
   - 단계별 전환 + 내레이션
   - 모니터링 화면
   - 한 줄 메시지(15초)
   - 롤백 명령과 두 개의 터미널(명령·모니터링)을 준비하고, 최소 1회 전체 리허설
4. **트리거 동선을 짧게 설계합니다.** 예: 커밋(또는 딸깍) → 알림 카드 → 대시보드로 이동. Orange는 이 동선을 30초 안에 보여주도록 설계했습니다.
5. **안전장치는 두되 목업은 밝힙니다.** Orange는 Mock/Real 전환으로 장애에 대비했습니다. 2026은 목업임을 밝혀야 하는 규칙이 있으니, 폴백을 쓸 때 그렇게 말하는 것을 대본에 넣습니다.
6. **수치에는 측정 방법을 한 줄 붙입니다.** 도구, 동시 사용자, 요청 패턴, 측정 지점을 함께 적고, 스크립트와 결과를 저장소에 커밋합니다. Orange·Blue·Green 모두 이 근거가 빠져 있었습니다. GPT가 예로 든 "p50 11ms → 2.1ms" 같은 숫자는 **GPT가 지어낸 예시**라서 쓰면 안 됩니다.
7. **Well-Architected는 나열하지 말고 "데모 장면 하나 = 축 하나"로 보여줍니다.**
   - 신뢰성: 헬스체크 → 전환 → 롤백
   - 운영 우수성: IaC와 알림
   - 보안: 최소 권한
   - 비용: 야간 중지 등
8. **보안은 스캐너가 아니라 아키텍처 속성으로 보여주되, 코드에 실제로 있어야 합니다.** 빌드와 실행의 권한 분리, private subnet, AI 권한 범위 같은 것입니다. Green은 워커 최소 권한이 README에만 있었습니다. 보안 도구 보류 결정과는 충돌하지 않습니다.
9. **문서와 코드를 일치시킵니다.** 수상작 셋(Orange·Blue·Green) 모두 README와 실제 구현이 어긋났습니다. 심사위원이 저장소를 열어볼 수 있으니 우리에게는 쉬운 가점입니다. 최종 스택 기준으로 README를 쓰고, 버린 모듈은 정리합니다.
10. **다중 사용자 데모 전에 앱 설정을 점검합니다.** Orange는 발표 당일 새벽에 레이트 리밋(분당 10)을 100으로 올렸습니다.
11. **(2026만 가능한 연출, 💭 후보)** 2025 1차 예선은 온라인이라 청중 참여형 연출이 어려웠습니다. 2026은 현장 발표라, 심사위원이 휴대폰으로 공개 URL에 접속하게 해서 "누구나 접근"을 직접 체감시키는 연출이 가능할 수 있습니다. 현장 Wi-Fi 사정에 좌우되니 확인이 필요합니다.
12. **주제 키워드를 기능으로 옮깁니다.** Orange는 "Delightful"을 Slack 제어·시각화·재미로 바꿨습니다. 우리는 2026 킥오프 문구로 같은 작업을 해야 합니다(아래 3절).

## 4. 버릴 것 (틀렸거나 2025에만 해당)

- **"1·2등은 Lambda를 안 썼다 → 관리형 서비스 조립만으로는 부족"**: 2025 본선 과제 자체가 "EC2 위에 FaaS를 직접 만들라"였습니다. 예선 교훈으로 옮기면 안 됩니다.
- **"AI 붙이기보다 인프라 깊이"**: 2025에는 AI 배점이 없었습니다. 2026은 AI 10점이 있고 주제 자체가 AI를 전제로 합니다.
- **"예선마다 2등까지 입상"**, **"블록코딩 IaC 팀"**: 미확인입니다. 블록코딩 팀은 환각일 수 있습니다.
- **Orange "필요한 Step만 선택"을 고급 기능처럼 해석하는 것**: 실제로는 테스트 포함/생략 2택이었습니다.
- **GPT가 예시로 쓴 성능 숫자**(p50·p95·cold start): 지어낸 값입니다.
- **"10분 발표"**, **"올해 예선 문제는 아직 모른다"**: 우리 조건은 5분 발표이고, 킥오프 자료를 이미 갖고 있습니다.

## 5. GPT 분석 총평

- **쓸 만한 부분:** 뼈대 공식(주제 해석 → 실무 불편 → 차별 UX → 클라우드 아키텍처 → E2E → 라이브 데모 → 측정값)은 우리 조사 결과와 일치합니다. 체크리스트로 쓰기 좋습니다. 탈락팀 블로그라는 새 1차 자료를 찾아낸 것도 성과입니다.
- **걸러야 할 부분:** README를 그대로 믿은 서술이 많습니다(Orange의 ECS 구성, 선택적 Step, 부하 테스트, Green의 IAM). 2025 본선의 교훈을 예선에 옮긴 부분과 2026 조건(AI 배점, 5분, 슬라이드 금지, 로컬+클라우드)을 반영하지 못한 부분도 있습니다.

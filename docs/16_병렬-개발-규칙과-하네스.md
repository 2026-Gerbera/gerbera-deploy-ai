## 2. MCP 서버 3개와 툴 배치 (💭 고려안, [I-1])

### 2-1. 서버 코드명 (💭 [I-3])

### 2-2. ① 플랜 툴 위치: A안 vs B안

| 선택지 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A안 (💭 권장)** | 검증 MCP = ① 플랜 7개 + `validate_plan` | MCP 툴 30개를 모두 같은 방식으로 호출. LLM 키는 `plan_mcp`·`report_mcp` 프로세스에만 들어감. 파이프라인 MCP·실행기·관리 API는 AI 0개가 되어 import 금지 계약을 깔끔하게 걸 수 있음 | 생성기(`generate_plan`)와 검사기(`validate_plan`)가 같은 프로세스. 완화: `validate_plan`은 순수 결정적 함수, `ddak_core.ai`·`generate_plan` import 금지(import-linter), 실행기가 계획 JSON을 받은 뒤 별도 호출로 검증. `receive_deploy_request`의 S3 업로드가 AI 서버에 AWS 쓰기 권한을 요구하는 문제 → [I-5] |

## 3. 저장소 구조 (💭 [I-6])

uv workspace 모노레포입니다. 파이썬 패키지는 모두 `packages/` 아래 src 레이아웃입니다.

```
ddak/                         # 저장소 루트 (이름 [I-2])
├── AGENTS.md  CLAUDE.md      # AI·사람 공통 작업 규칙 / "@AGENTS.md" + Claude 전용 주의
├── README.md  CONTRIBUTING.md  LICENSE  THIRD_PARTY_NOTICES.md
├── pyproject.toml  uv.lock  .python-version   # workspace 루트 + 도구 설정 전부, 단일 lock, 3.13
├── Makefile                  # scripts/dev.py 얇은 래퍼 (단일 진입점)
├── env.example               # 환경변수 키 목록(값 없음)
├── .claude/                  # settings.json(attribution 끄기·비밀 읽기 deny) + hooks/guard_bash.py(💭)
├── .githooks/                # commit-msg · pre-commit · pre-push
├── .github/                  # workflows/ci.yml, CODEOWNERS, allowed-authors.txt, commit-scopes.txt, PR·이슈 템플릿
├── packages/
│   ├── core/          → ddak_core          # 공용: contracts/(★계약), registry.py(★33개), adapters.py, mcp_kit.py,
│   │                                       #       runtime.py, config.py, runlog.py, redact.py, logging.py, ai/(★AI 관문)
│   ├── plan_mcp/      → ddak_plan_mcp      # 검증 MCP
│   ├── pipeline_mcp/  → ddak_pipeline_mcp  # 파이프라인 MCP (_aws/, _docker/)
│   ├── report_mcp/    → ddak_report_mcp    # 검증 및 보고 MCP (_aws/)
│   ├── executor/      → ddak_executor      # 실행기: ToolGateway, 서버 기동·env 허용목록, 잠금·롤백 트리거, 승인, 이벤트 버스
│   └── admin_api/     → ddak_admin_api     # 관리 페이지 백엔드(FastAPI + SSE), 실행기와 같은 프로세스
├── apps/                     # workspace 밖
```

## 5. 툴 작성 규약과 AI 경계 강제

### 5-1. 툴 하나의 구성 (💭 형식, ✅ "툴 하나 + 환경별 어댑터" 원칙)

| 파일 | 역할 |
|---|---|
| `tools/<tool>/tool.py` | `register(server)`: MCP 등록. 입력 모델 → 어댑터 선택 → 호출 → 출력 모델 반환. 로직 없음 |
| `tools/<tool>/logic.py` | (선택) 환경 무관 공통 로직 |
| `tools/<tool>/local.py` / `cloud.py` | LocalAdapter / CloudAdapter (target이 있는 툴만) |
| `tools/<tool>/fake.py` | FakeAdapter: 결정적 정상/실패 시나리오(테스트·드라이런·UI 개발) |
| `tools/<tool>/prompt.md` | AI 툴만: 프롬프트. 머리말에 버전·담당·변경일 |
| `packages/<server>/tests/tools/test_<tool>.py` | 툴 테스트 |
| `ddak_core/contracts/tools/<tool>.py` | `<Tool>Input` / `<Tool>Output` (1툴 1파일) |

- 레지스트리의 툴 디렉토리는 처음에 만들지 않습니다. 담당자가 `ping` 템플릿을 복사해 만듭니다.

### 5-2. 입출력 모델 규칙 (💭)
1. 모든 툴은 `contracts/tools/<tool>.py`의 pydantic 모델만 받고 반환합니다. 원시값·dict 반환은 금지합니다(MCP 구조화 출력의 `{"result": ...}` 래핑 차이를 없애기 위해).
2. 모델은 `ContractModel`(`extra="forbid"`, `frozen=True`)을 상속합니다.
3. 입력은 좁게 받습니다.
   - `run_id`는 모든 툴의 필수 입력입니다.
   - `target`(local|cloud)은 target이 있는 툴만 받습니다.
   - `tier`는 문자열 패턴(`^[a-z][a-z0-9_-]{0,31}$`)으로 받습니다. 프로젝트마다 다르므로 정적 enum으로 두지 않고 실행 시 `deploy.yaml`과 대조합니다.
   - ④ 툴은 `lock_token`을 받습니다.
   - 자유 문자열 명령, 빌드 명령 재정의, IAM 역할 재정의는 입력으로 열지 않습니다([10](10_전체-흐름-초안.md) 6절).
4. 비밀값 필드(예: `sync_env_to_cloud`의 값)는 `SecretStr`로 둡니다. 로그·이벤트·run 로그·계획 JSON·AI 입력 어디에도 남기지 않습니다.
5. AI 툴 출력에는 `ai_usage`(모델, 토큰, 비용, 지연)와 `source`("live" / "cache" / "fixture")를 넣습니다. 관리 페이지는 `source`가 live가 아니면 라벨을 표시합니다.
6. 필드 정의 자체는 `TODO(contract)`입니다. 공통 계약 문서가 정합니다.

### 5-3. 레지스트리 (💭)
- `ddak_core/registry.py`에 `ToolSpec` 33개를 정적으로 선언합니다. 필드: `name`, `stage`, `server`, `kind`, `uses_ai`, `owners`, `targets`, `destructive`, `read_only`, `requires_lock`, `requires_approval`.
- **서버 배치의 유일한 출처**입니다(`TOOL_TO_SERVER`). 실행기와 `validate_plan`은 서버 코드를 import하지 않고 이 표만 봅니다.
- 툴을 등록할 때 `mcp_kit`이 레지스트리와 대조합니다. 이름·서버·플래그가 다르면 서버 기동에 실패합니다.
- MCP ToolAnnotations는 레지스트리에서 채웁니다(destructive → `destructive_hint`, read_only → `read_only_hint`).

### 5-4. 실패 보고 규약 (💭)

| 상황 | 방법 | 실행기 동작 |
|---|---|---|
| 작업을 수행할 수 없음(잠금 실패, 어댑터 타임아웃, 입력과 `deploy.yaml` 불일치, 인프라 없음) | `ToolError("<ErrorCode>: 메시지")` → `is_error=True` | 중단, 해당 환경 롤백 판단 |
| 검사 결과 불합격(스모크·헬스·TLS 불합격) | 정상 반환 + `passed=False` + 상세 | 규칙 롤백 → `diagnose_parity_gap` |
| 예상하지 못한 예외 | SDK가 메시지를 정제, 트레이스백은 서버 stderr에만 | 중단, run 로그의 stderr로 원인 확인 |

- ErrorCode 초기안(💭, 확정은 계약 문서): `PLAN_INVALID`, `LOCK_HELD`, `LOCK_INVALID`, `CONFIG_INVALID`, `INFRA_MISSING`, `ADAPTER_TIMEOUT`, `ADAPTER_FAILED`, `PRECONDITION_FAILED`(로컬 스모크 미통과 등), `APPROVAL_REQUIRED`, `APPROVAL_DENIED`, `TOGGLE_OFF`, `AI_NOT_ALLOWED`, `AI_UNAVAILABLE`, `AI_OUTPUT_INVALID`, `INTERNAL`.
- 에러 메시지에 비밀값, 절대 경로, 계정 ID를 넣지 않습니다. 이 메시지는 관리 페이지와 LLM으로 흘러갑니다.

### 5-5. MCP SDK·스펙 규칙 (💭)
- **MCP Python SDK v2 전용**, `mcp[cli]>=2.2,<2.3`로 고정하고 3일 동안 minor 업그레이드를 금지합니다.
  - v1의 `mcp.server.fastmcp`는 v2에서 import 오류가 납니다. ruff banned-api로 금지합니다.
  - AI 코딩 도구는 v1 코드를 만들기 쉽습니다. **TL이 설치해 동작을 확인한 `ping` 템플릿만 복사합니다.**
  - ⚠ v2 API는 문서로만 확인했고 설치해서 돌려보지 않았습니다. 템플릿의 SDK 호출부에는 `TODO(verify-sdk)`가 붙어 있고, TL이 첫날 `make check`로 고칩니다.
- stdio 서버에서 stdout은 JSON-RPC 채널입니다. **`print` 금지**(ruff T20). 로그는 stderr JSON 한 줄(`ts, level, run_id, server, tool, target, msg`).
- boto3·Docker 호출은 blocking입니다. `async def` 안에서 직접 부르지 않고 sync 함수나 `anyio.to_thread`를 씁니다. Docker는 `subprocess` 리스트 인자로 부릅니다(`shell=True` 금지).
- 33개 툴 이름은 서버 전체에서 유일해야 하고, 테스트로 강제합니다.

### 5-6. AI 경계 강제 (네 겹, 💭)

| 겹 | 수단 | 잡는 것 | 한계 |
|---|---|---|---|
| 1 정적 | import-linter 계약 | 실행 경로에서 AI 모듈·LLM SDK import(간접 포함) | 동적 import는 못 잡음 |
| 2 정적 | ruff banned-api(TID251) | `anthropic`·`openai`·`mcp.server.fastmcp` import (`ddak_core/ai/providers/**`만 예외) | 같음 |
| 3 런타임 | `call_ai` 가드: 현재 툴(contextvar)이 레지스트리의 `uses_ai=True` 툴이 아니면 `AI_NOT_ALLOWED` | 허용 안 된 툴에서의 호출 | – |
| 4 물리 | 실행기가 서버를 띄울 때 env 허용목록 적용: pipeline_mcp·실행기·관리 API에는 LLM·Jev 키를 주지 않음. report_mcp에는 읽기 전용 AWS 프로필만 | 키가 없으니 호출 자체가 불가능 | 같은 머신에서 사람이 직접 설정하는 경우 |

import-linter 계약(💭, 계약 타입·키 이름은 import-linter 문서로 확인):
1. **forbidden:** `ddak_pipeline_mcp`, `ddak_executor`, `ddak_admin_api` → `ddak_core.ai`, `anthropic`, `openai` 금지.
2. **protected:** `ddak_core.ai`는 AI 툴 7개 모듈만 import(`plan_mcp`의 analyze_project·generate_plan·patch_* 3개, `report_mcp`의 diagnose_parity_gap·post_report).
3. **independence:** 서버 3개와 실행기는 서로 import하지 않음. 실행기는 서버를 프로세스로만 부름.
4. **forbidden(A안):** `validate_plan` → `ddak_core.ai`, `generate_plan` 금지.
5. **forbidden:** 서버 3개 → `ddak_admin_api` 금지.

`tests/contract/` 검사: `uses_ai` 집합이 정확히 7개인지(스냅샷), pipeline_mcp 실행 env에 LLM 키 이름이 없는지, 허용 밖 툴에서 `call_ai`를 부르면 예외가 나는지.
→ 발표 때 "실행 경로에 AI 없음"을 CI 결과와 프로세스 env로 보여줄 수 있습니다.

### 5-7. 신뢰하지 않는 입력 처리 (✅ 원칙, 💭 방법)
- git diff와 코드는 프롬프트에 **데이터로만** 넣습니다. 구분자로 감싸고, 지시문으로 해석하지 말라는 시스템 지시를 둡니다.
- LLM 출력은 항상 pydantic으로 파싱합니다. 실패하면 재지시는 최대 1~2회, 그다음은 규칙 기본 계획입니다.
- 패치는 코드로 바로 실행하지 않습니다. 데모 작업 사본에 적용하고 **사람 승인 뒤에만** 반영합니다. 토글 OFF면 두 번 막습니다(툴 목록에서 제거 + `validate_plan` 불합격).

### 5-8. 스키마 스냅샷과 완료 기준(DoD) (💭)
- `make contracts`: 계약 모델의 JSON Schema와 서버별 tools/list 스냅샷을 다시 만들어 커밋된 파일과 비교합니다. CI도 같은 검사를 합니다.
- **툴별 DoD:** 인메모리 Client + Fake 어댑터로 정상 1개·실패 1개 테스트, 스키마 스냅샷 커밋, 레지스트리 대조 통과.
- **테스트 필수 영역(작성 순서·TDD 여부는 자유):** `validate_plan`, 계약 모델, AI 경계, `redact`, `git_guard`, `patch_eval`. 나머지는 스모크 위주입니다.
- 커버리지 수치 게이트는 두지 않습니다.

## 6. 명령 표준 (💭, 단일 진입점)

- 모든 명령의 실제 구현은 `scripts/dev.py`(표준 라이브러리) 하나에 있습니다. `Makefile`은 얇은 래퍼입니다.
- AGENTS.md, CONTRIBUTING, CI, 역할 가이드는 **`make <타깃>`만** 가리킵니다. 명령을 여러 곳에 복붙하지 않습니다(devpi에서 4곳의 명령이 서로 달라진 교훈).
- Windows 사용자는 `python scripts/dev.py <작업>`을 씁니다. `setup`만 uv 설치 전에도 동작합니다.
- 담당자가 아직 구현하지 않은 작업은 "미구현(담당 X)"을 출력하고 종료 코드 3으로 끝납니다.

### 7-1. 브랜치·커밋·PR (💭 [I-10])

| 항목 | 규칙 |
|---|---|
| 브랜치 | `<역할>/<주제>`. 역할은 `c1, c2, c3, o1, o2, o3, tl`, 주제는 영문 kebab-case(예: `o1/executor-gateway`). 반나절 이하로 짧게. main 반영은 merge·rebase 모두 허용(squash 병합이라 main 이력은 어차피 한 줄). rebase 뒤 자기 브랜치 강제 push는 사람이 `--force-with-lease`로. 형식 위반은 pre-push에서 경고만 |
| 커밋 메시지 | `<type>(<scope>): <요약>`. scope 필수, 요약 72자 이하, 끝에 마침표 없음. type: `feat, fix, refactor, perf, test, docs, build, ci, chore, revert`. scope는 `.github/commit-scopes.txt` 18개만: `core, contracts, ai, plan-mcp, pipeline-mcp, report-mcp, executor, admin-api, admin-web, sample-app, infra, compose, fixtures, scripts, harness, ci, docs, deps`. 요약 언어 [I-20]. `Merge`, `Revert`, `fixup!`, `squash!`, `amend!`는 형식 검사 제외 |
| PR | 작게(생성물·lock 제외 약 400줄 이하 권장). Draft를 일찍 열어도 됨. PR 제목도 커밋 형식(squash 결과가 제목이 되므로). 리뷰 1명 승인(CODEOWNERS는 리뷰어 자동 지정용) + CI 필수 체크 3개. 병합은 squash만 |
| 라벨 (선택) | `contract-change`, `security-sensitive`, `demo-blocker`, `needs-context`. 안 붙여도 머지를 막지 않음 |
| security-sensitive | `ddak_core/ai`, `redact.py`, IAM·Terraform IAM, 비밀 흐름(`sync_env_to_cloud`, `inject_env_config`), 잠금·롤백, 패치 적용, CI·훅·`.claude`를 건드리는 PR. TL 또는 C1이 추가 리뷰. (선택) 새 에이전트 리뷰 1회, 수정 반복 최대 2회 |
| main 보호 | **첫 main push(TL, 하네스 + 허용목록만) 직후** 켬(먼저 켜면 첫 push가 막힘). PR 필수, 승인 1명, 필수 체크 `ci / quality`·`ci / attribution`·`ci / secrets`, force push·삭제 금지, 관리자도 우회 금지, squash만 허용, squash 기본 메시지 = PR 제목(💭). "Code Owners 리뷰 필수"는 💭 선택: `*` 기본 줄 때문에 모든 PR이 특정 담당 승인을 기다리게 되어 6명·3일에는 병목이 될 수 있음 |
| 사람만 하는 일 | merge, force push, 첫 main 생성(TL 1회, 이후 main 직접 push는 누구도 안 함), 태그, `terraform apply/destroy`, AWS 리소스 삭제, 비밀값 입력, 저장소 설정 변경 |

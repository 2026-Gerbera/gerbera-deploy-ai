- 요청 요약: 원본 flaskr(pallets/flask `d73fa1c`)를 v1 익명 게시판으로 옮기는 작업. 범위는 SQLAlchemy·MySQL 8.4, `/health/*`·`/version`, 마이그레이션 러너(C-09), 기준 Dockerfile(was·web)과 nginx 템플릿, `deploy.yaml`, 개발 환경 파일, 라이선스 고지.
- AI 산출물: 부분 채택. 사람이 검토한 뒤 사람 계정으로 커밋한다. 에이전트는 커밋·push를 하지 않았다.
- 사람이 판단하거나 수정한 것: 오래된 로컬 문서를 버리고 저장소 문서를 기준으로 삼았다. v1을 먼저 한다.
- 확인한 것:
  - MySQL 8.4.11 컨테이너에서 마이그레이션 전 ready 503 → 러너 `precheck → up → verify` 통과 → ready 200.
  - `up`을 다시 실행해도 아무것도 적용하지 않는다. 이미 있는 0002 문장은 문장 단위 가드로 건너뛴다.
  - 파괴형 문장은 precheck에서 실패하고, 빈 DB에서 verify는 exit 1이다.
  - 결과 줄은 O1 `_MigrationResult`(extra=forbid) 모양과 맞는다.
  - v2 스키마(0002)에서도 v1 코드의 목록·글쓰기가 정상이다.
  - 응답에 Set-Cookie가 없다. hadolint 경고가 없다.
  - `deploy.yaml`은 O2 `DeployConfig`(PR #3로 main에 병합)로 검증했다.
- 문제와 교훈:
  - 설계 문서의 `deploy.yaml` 예시와 O2 모델(extra=forbid)은 형식이 다르다. 코드가 검증하는 쪽(O2 모델)에 맞췄다.
  - 주석에 서명 키 이름이나 메시지 함수 이름이 있으면 V1-1·V1-2 grep과 분석 스캐너에 걸린다. 그래서 주석에도 쓰지 않는다.

# O1 AI 활용 기록

## 2026-09-30 | Codex | 하네스 최신화와 로컬 착수

- 요청: 최신 문서·사용자 결정 반영, 로컬 개발환경 구성, O1 우선 계약 정리.
- 사람이 결정한 것: 한 화면·한 번 승인, 대상별 기록 분리. O1 착수 기준 정리는 위임.
- AI 산출물: 독립 테스트와 계약 모델, 비Git 환경 준비 명령, 문서 정합성 수정. 실제 배포 기능 완성은 범위 밖.
- 검증 결과는 하네스 README의 현행 검증 기록을 참조한다. 사용자 요청으로 TDD 절차는 중단하고 기존·추가 테스트와 전체 품질 검사로 검증했다.

## 2026-09-30 | 최소 협업 규칙으로 조정

사용자 요청으로 이메일 허용목록·커밋 형식·브랜치명·main push·필수 PR 승인 제약을 제거했다. CI 자동 검사와 AI 작성자 표시 차단은 유지한다. GitHub 업로드·설정 변경은 수행하지 않았다. TDD 없이 기존 동작·변경 동작을 로컬 검사로 확인한다.

## 2026-09-30 | 하네스 루트 이동

사용자 요청으로 구형 MCP 하네스를 삭제하고 최신 하네스 148개 파일을 저장소 루트로 이동했다. 이동 직후 파일 해시 일치를 확인했다. Git 저장소·프로젝트명·설계 문서·조사 자료는 보존하고 상대 링크와 로컬 경로를 수정했다. 루트에서 가상환경을 다시 구성해 검증한다.

## 2026-09-30 | 사용자 경로 정정

최상위라는 요청은 저장소 루트에 `harness/` 폴더를 두라는 뜻이었다. 하네스를 이 폴더로 이동하고, 루트 GitHub Actions가 `harness/`를 검사하도록 변경했다. 로컬 훅과 setup도 상위 Git 저장소를 지원하도록 조정한다. 이전 루트 이동 기록은 경로 정정 전 이력이다.

## 2026-09-30 | O1 실행기·온프렘 구현

- 사용자 결정: O1 개발 계획 실행, TDD 생략, 한 번 승인과 대상별 기록, 교차 검증 실패는 클라우드만 롤백하고 로컬 v2 유지.
- 구현: SQLite 실행 장부·프로젝트 잠금, 승인/소스/빌드 결합, 실행기 갱신·취소·실패 처리, Docker provider, CD 등록 툴, fixture 리허설·초기화, 관리 앱의 실행 서비스 연결.
- 검증: 구현 후 집중 테스트와 독립 검토. 실제 Docker 테스트 앱에서 HTTP 버전 변경·복구, 시크릿 재사용, 마이그레이션 러너 멱등성, 서비스 경유 반복 업데이트를 확인한다. 현재 결과와 범위는 [O1 가이드](../guides/O1.md), 재실행 증거는 `var/validation/onprem-runtime.json`이다.
- 검토에서 수정: 실행 종료 미확인 상태의 롤백 차단, 패리티 실패 클라우드 복구, 빌드 결과 전파, UI 구독 격리, 정상 파일명에 대한 해시 마스킹 오류, 환경별 성공 기록 보존, 최종 저장 실패 처리.
- 제한: 실제 O3 앱/MySQL·C2 CodeBuild/AWS·AI 호출·C3 승인 화면은 팀 통합 대상이다. fixture 시간을 전체 라이브 데모 시간으로 제시하지 않는다. 커밋·푸시는 수행하지 않았다.
- 후속 검토 수정: diff 본문과 헤더 구분, tier별 롤백 시간 합산, 로컬 전용 실행의 환경 기록, SQLite 잠금 갱신 재시도·실패 중단. 수정 후 전체 검사 358개와 실제 Docker 반복 배포·복구를 다시 통과했다.
- 종료 시 진행 중인 heartbeat 결과를 확인한 뒤 봉인하도록 수정하고, SQLite 쓰기 잠금 획득 뒤 만료를 판단한다. 해당 경합과 Unicode diff 회귀 검사를 추가한 최종 전체 검사는 362개 통과했다.
- 내부 집중 재검토는 수정 소스 기준 PASS. 외부 최초 검토 지적은 수정했으나, 허용된 1회 재검토 응답의 대상 목록이 전송 목록과 일치하지 않아 최종 외부 판정은 `UNAVAILABLE`로 남겼다. 외부 검토 통과로 주장하지 않는다. 기록: `var/validation/external-review-focused.json`.

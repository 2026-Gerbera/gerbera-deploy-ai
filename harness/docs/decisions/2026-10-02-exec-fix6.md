# 후속 수정 6 결정·취합 메모

- 정준우 확정: 마이그레이션 step ID를 `deploy.migrate.<env>`로 변경한다. 온프렘 MySQL 컨테이너 step은 `deploy.db.local(deploy_tier)`이다. `plan/validate`는 문자열만 최소 수정했고 담당자 확인 목록에 기록한다.
- DB 이미지 출처는 현행 온프렘 CLI와 같은 앱 소스의 `images.lock.json` 중 `mysql` 항목을 재사용한다(선택 나). `ref`, `index_digest`, `platform_digests`(amd64/arm64)를 검증한다. 승인된 수정본에서 읽으므로 패치/소스 해시와 결합된다. 인벤토리와 DeployConfig에 새 필드를 넣지 않는다.
- DB는 빌드하지 않는다. supplied artifact가 있어도 `build.db` 계획과 비공식 이미지를 거부한다. local DB 이미지를 cloud 컨테이너 DB에 함께 사용하는 계획도 거부한다. 클라우드 DB 연결은 O2/C2 인프라 역할에 맞춰 별도로 취합한다.
- O2 요청: 카탈로그/규칙에서 local DB 선행 배포와 build.db 제외를 연결하고, R-migration의 선행 조건에서 DB 컨테이너를 예외 처리해야 한다. 현 단계의 수동 3티어 실행 성공은 자동 계획 생성 완료가 아니다.
- 미빌드 tier의 이미지는 환경별 성공 장부에서 가져와 승인 컨텍스트에 고정한다. FAKE 기록으로 REAL 이미지를 공급하거나 NEEDS_HUMAN 기준으로 진행하지 않는다. 이월 artifact를 새 빌드 snapshot에 섞지 않고 관측·출처를 환경 image_sources에 보존한다.
- FAKE 인프라는 fixture임을 승인 요약과 실행 결과에 표시한다. REAL에서 fixture를 받지 않는다. 제품의 승인·잠금·plan 무결성 경로는 일반 InfraRuntime을 그대로 사용한다.
- 경로 기준은 설정을 읽는 순간의 실행 위치다. 표준 `make -C harness`는 harness를 기준으로 하며 이후 Git subprocess의 cwd에 영향받지 않는다. 기존 경로 배치를 옮기지 않고 절대 경로로 고정한다.

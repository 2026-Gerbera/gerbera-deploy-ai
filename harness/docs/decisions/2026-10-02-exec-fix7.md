# 후속 수정 7 — PR #12 연동 계약

정준우가 후속 수정 7의 1~5를 승인한 범위다. 기준 merge `e82d11a`, 브랜치 `o1/exec-fix6`. 실제 AWS·VM·Terraform 실행과 commit/push/PR은 하지 않는다.

## 출력과 저장

- 플랫폼 출력은 기존 `cluster_name`, `public_subnet_ids`를 유지하고 `ecs_service_name`, `target_group_arn`, `app_security_group_id`를 추가한다.
- ECS 컨테이너 이름은 `web`/`was`다. `ecs_container_name_<TIER>` 출력은 만들지 않는다. `region`도 출력이 아니며 `ddak.app`이 cloud 컨텍스트에 `ap-northeast-2`를 주입한다. C2/C3 소비자는 같은 기본값을 사용한다.
- `APP_OUTPUTS`와 `app_secret_arn_<KEY>`도 릴리스의 기존 `platform_outputs` 필드에 보존한다. 필드명은 호환성을 위해 유지하되 이제 두 층의 허용된 출력 집합을 담는다. 저장·조회 시 층을 분리해 `checked_outputs`로 검사하고, ARN·이름·서브넷 ID 목록만 저장한다. 시크릿 값은 받지 않는다. `region` 등 조립 설정은 저장하지 않는다.
- 출력 목록은 허용 목록이며 모든 run에 전체 키를 강제하는 목록이 아니다. 초기 생성 전 컨텍스트와 app 단독 apply를 허용한다. runtime은 해당 번들에 선언된 출력의 누락·sensitive를 거부하고, 서비스별 필수 키 검사는 각 소비자 책임으로 유지한다.
- `IMAGE_REPOSITORY_PATTERN`은 `core/contracts/infra_outputs.py`의 공통 상수다. `checked_outputs`와 C1 출력 선언 검사는 이 패턴을 사용한다. C2 `docker_hub_repo` 적용은 담당자 요청이다.

## ECS 배포 소유권

- task definition의 컨테이너 이름은 중복 없이 `web`/`was`만 허용한다. 임의 이름·미확정 이름은 거부한다.
- service HCL의 `lifecycle.ignore_changes`는 최소 `task_definition`, `desired_count`를 명시해야 한다. `deployment_circuit_breaker`는 `enable=true`, `rollback=true`가 필수다.
- 컨테이너 이름·회로 차단기는 plan의 실제 값에서도 검사한다. lifecycle은 Terraform plan의 리소스 after에 없으므로 HCL 검사와 승인 번들 해시로 고정한다. 이 설정은 Terraform 재적용이 C2의 배포 리비전·복제본 수를 되돌리지 않게 한다.

## 이월 이미지

- provider 조회 경로는 `ctx.previous_release["cloud"]["image_sources"][tier]`다. 이월 항목은 `CarriedImageSource` 계약을 만족하며 `.artifact`는 기존 `ImageArtifact`다. JSON Schema는 `carried_image_source.json`으로 내보낸다.
- O1은 prepare에서 artifact의 ref/index/amd64·arm64 digest와 환경 장부의 이미지 참조 일치를 검사한다. 승인 후 기준이 바뀌면 기존 비교로 거부한다. 실행 컨텍스트는 레거시 장부의 `artifacts.images[tier]`도 위 경로로 정규화한다.
- 새 `release_artifacts`는 이번 빌드만 담는다. 이월 artifact를 새 snapshot으로 재귀속하지 않는다. target별 이전 digest와 관측을 분리하며, FAKE 상태는 REAL 기준으로 쓰지 않는다.

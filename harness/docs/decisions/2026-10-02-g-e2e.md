# 작업 G — E2E 연결 (10/2)

사용자 최신 순서: **1 → 2 → 9 → 3 → 4 → 8 → 5 → 6 → 10 → 7**.
1차는 Flask 기본 앱 → 이미지·박스 추가 → v1 재배포이며 DB 스키마 변경·auth 추가 없음.
2차에서 LLM 분석·패치·인프라 생성 검증을 진행한다. 실제 AWS/GitHub/VM 접속과 commit/push/PR 금지.

- G1: 감지 SHA로 intake를 고정하고 plan→prepare를 연결. RunContext에 선택 필드 repo_url/ref 추가(사용자 G1 지시). contracts-update 실행, 현재 exporter의 schema diff 없음. 실패 단계·안전한 오류·미등록 툴 이름을 조회 기록에 보존하며 Watcher 제한 재시도를 유지한다. `DDAK_ONPREM_INVENTORY`는 onprem 선택 때만 읽는다.
- G2: 승인 입력은 0600 SQLite prepared_runs에 보관하고 원래 해시로 복원한다. 표시용 redact JSON은 복원 원본으로 쓰지 않는다. 감시/수동 intake 소스는 상태 디렉토리 sources/run_id로 복사한다. RUNNING 중단은 기존 NEEDS_HUMAN, 저장되지 않은 구형 pending만 CANCELLED. 커스텀 facts_reader는 재기동 시 같은 키로 명시적으로 주입해야 한다. 임의 함수 import/역직렬화 없음.
- G1/2 독립 검토: 재시도·실패 사유·cloud 전용 인벤토리·승인 컨텍스트 보호 교정. 계획 도중 설정 변경은 prepare(expected_settings_version)로 최종 확인해 이전 계획에 새 설정이 붙지 않게 한다.
- G9: migration 전용 파일에 DATABASE_URL_MIGRATOR가 있으면 DATABASE_URL도 같은 값으로 공급. 기존 SQLite DATABASE_URL만 있는 파일도 허용. 앱 env와 migration env를 분리하고 빈 URL은 실행 전 거부. RELEASE_ID는 run_id, SOURCE_SHA는 candidate_sha로 컨테이너 생성 시 주입, rollback은 이전 릴리스 값을 사용한다.
- **NEEDS_CONTEXT (G9d):** 기존 VM temp-box의 flaskr DB/볼륨은 보존한다. 새 앱은 별도 DB 이름(예: gerbera_application)과 전용 앱/마이그레이션 계정을 생성하는 안을 제안한다. 이름·권한 확정과 ensure_app_database 구현은 준석님 범위이며 이번에 생성/접속하지 않았다.
- **준석 요청 (G9c):** analyze가 코드의 os.getenv 기본값을 발견해 env_keys로 보내고, 계획의 inject_env_config가 host env를 필수로 검사하는 연결을 확인했다. APP_ENV/MIGRATE_MODE 등 앱 내부 기본값을 외부 필수 키와 구분해야 한다. onprem/config.py의 누락 거부를 우회하지 않았다.
- G3: 수동 API는 감시 브랜치 또는 v* 태그만 받는다. 태그는 refs/tags/로 한정해서 동명 브랜치로 해석되지 않게 한다. 기본 대상은 요청 생성 때만 적용한다.

공유/담당자 검토: 선택 RunContext 필드와 prepare의 선택 인자 추가, 기존 app 감시 테스트의 무효 context=None fixture를 유효한 승인 입력으로 교체했다. plan/* 생산 코드·watch.py·web/*는 변경하지 않았다.

- G4: 로컬 bare 저장소에서 v1 수동 → prod 새 커밋 감지로 v2 이미지·박스 → v1 태그 수동 재배포를 검증했다. 후보 SHA·환경별 태그·main·릴리스 기록을 함께 검사했다. 외부 도구는 테스트 안에서만 가짜 등록했다. 실제 서버/빌드/LLM 성능 검증과 구분한다.
- G8: apply_diff는 hunk마다 바로 앞의 ---/+++ 쌍을 요구한다. diff --git/index/mode/rename/copy 등 확장 메타를 거부하고 실제 변경 파일 집합과 파싱 경로를 대조한다. 한 헤더 아래 여러 hunk가 있는 일반 diff는 현재 계약에서 거부하므로 O3는 파일별 한 hunk로 정규화해야 한다. 기존 O1 v2.patch의 diff --git 헤더만 제거했다.
- G5: apply_infra가 선택된 경우 조립된 InfraBinding으로 validate_infra → plan_infra를 실행해 plan SHA와 C-18 요약을 승인 대상으로 고정한다. 번들/세션이 없으면 generate_infra 누락을 명시해 실패한다. **NEEDS_CONTEXT:** 생성기 출력과 binding 조립 계약은 준석 합의 필요. 재시작 후 binding은 기존 승인 plan을 가리키도록 재주입하며 승인 후 재생성하지 않는다.
- G6: 실행기는 O2가 확정한 최종 steps만 소비한다. include/forced_skip을 다시 해석해 단계를 추가하지 않는다. modified_migrations는 경고로 보존하며 prepare_db 입력은 신규 마이그레이션만 유지한다. 회귀 검증 결과 실행기 생산 코드 추가 변경은 필요하지 않았다.
- G10: compare/diagnose의 passed=False만 패리티 실패다. 미등록/예외는 FAILED_VERIFY(비교 불가)이고 환경 롤백을 하지 않는다. 이때 성공한 환경의 deployed 태그는 기록하되 main 승격은 막는다. AppRepository.publish의 선택 인자 update_main 기본값은 True로 기존 호출을 보존했다. 기술적 비교 실패 뒤 diagnose를 실행해 불일치를 추정하지 않는다.
- 운영 연결: app.create 기본 factory는 아직 앱 checkout/repositories 매핑을 자동 구성하지 않는다. 운영 경로를 확정하고 O1 조립을 마쳐야 실제 후보 생성·게시가 가능하다. O2 감시의 main→prod와 C2/O3 도구 등록도 별도 인계 대상이다.

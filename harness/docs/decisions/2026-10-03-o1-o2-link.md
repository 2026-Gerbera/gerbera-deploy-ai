# 10/3 O1↔O2 연결분 분리

정준우의 10/3 지시. 기준 `origin/main` 8a2c3b8, 브랜치 `o1/o2-link`, 작업 사본 `.worktrees/o1-o2-link`. 원래 수정 8 작업 트리는 보존하며 연결에 필요한 변경만 이식했다. 커밋·push·PR은 사람이 한다.

## 결정과 범위

1. 마이그레이션 계정 키는 `core/env_keys.py`의 대소문자 무시 `*_MIGRATOR` 규칙으로 런타임 분석·온프렘·Fake 주입에서 제외/거부한다. BOOTSTRAP env_example 키를 신규로 분류한다.
2. OPTIONAL step은 등록된 툴만 조립한다. AI의 include보다 코드 검증이 우선이다. `registered_tools` 선택 인자로 독립 테스트 가능하며 경고를 남긴다.
3. 환경 툴 미등록은 해당 트랙의 준비 실패다. `RunContext.preparation_failures`를 승인 해시에 묶고 실행 시 실패한 트랙은 시작하지 않는다. 정상 트랙은 계속된다. 공통 빌드 미등록·선택한 모든 환경 준비 실패는 요청 단계에서 거부한다. 실제 로컬 인벤토리 검사도 실패하지 않은 로컬 트랙에만 적용한다.
4. 감시 기본값은 flaskr/local/prod, 프로젝트 설정의 기본 대상은 onprem이다. 저장 설정이 우선이며 없는 프로젝트에만 선택적 감시 환경변수를 적용한다. flaskr 설정이 없고 demo만 있으면 demo 장부를 그대로 쓴다.
5. 판단 역할은 `DDAK_JEV_BACKEND=groq|claude-cli`로 선택한다. Groq는 `DDAK_GROQ_*`만 사용하며 예약된 `DDAK_JEV_API_KEY`는 외부로 보내지 않는다. 생성 역할 설정은 기존 cli/api/replay를 유지한다. 실제 판단 provider/model과 fixture 출처를 기록한다.
6. Claude CLI 기본은 claude-sonnet-5-5, effort low(선택 medium). 생성 역할 cli와만 모델 설정을 공유한다. 생성 역할 api/replay 모델을 Claude 판단 argv에 전달하지 않는다. CLI는 loopback의 로컬 진입점에서만 허용한다. `claude --help`만 확인했으며 실제 호출은 안 했다.
7. 공유 모델 변경: RunContext.preparation_failures, EnvKey.provider/model 선택 필드. contracts-update로 분석/계획 관련 JSON 스키마 3개를 갱신했다. 기존 필드 의미는 유지한다.

로컬 빌드·후보/gitleaks 사전 검사·store/대체됨/잠금 해제·웹·풀체인 스크립트/런북은 제외했다. 이 분리 작업은 온프렘 실환경 배포 완료 주장이 아니다.

## 준석님께 전달 — 확인 필요

- 로컬 셸의 판단 키/모델을 **DDAK_GROQ_API_KEY·DDAK_GROQ_MODEL**로 옮겨야 Groq가 계속 동작한다. 선택 timeout은 DDAK_GROQ_TIMEOUT_S다. DDAK_JEV_API_KEY로 대체하지 않는다.
- 판단 backend는 DDAK_JEV_BACKEND, 생성 backend는 DDAK_LLM_BACKEND다. Claude 사용은 cli 모델/effort 설정과 로컬 실행 경계를 확인한다.
- 감시 보조 환경변수는 DDAK_WATCH_REPO_URL, DDAK_WATCH_PROJECT, DDAK_WATCH_TARGETS, DDAK_WATCH_BRANCH. 저장된 프로젝트 설정이 우선이다.
- 마이그레이션 키는 runtime env_keys에서 제외됐다. 전용 migrate 경로로만 전달한다. BOOTSTRAP env_example 신규 판정을 확인한다.
- 수정한 O2 파일: core/ai/gateway.py, providers/{__init__,api,cli,jev,claude}.py, core/ai/status.py, plan/analyze/logic.py, plan/planner/logic.py, plan/intake/watch.py, plan/validate/{__init__,assemble}.py 및 관련 테스트·O2 가이드.
- OPTIONAL 미등록은 제외되지만 필수 환경 툴은 해당 환경 준비 실패로 남는다. 앱 조립에서 missing_track_tools 검사와 prepare 재계산을 사용한다.
- 남은 O2 요청: required(name) 래퍼 분석, 내부 기본값 키(APP_ENV 등) 구분, 대상 환경만 이전 manifest에 전달, DB tier 자동 계획 순서/클라우드 DB 제외. 이번에 고치지 않았다.
- 분류가 plain으로 내려가는 현재 동작은 유지했다. README의 승격만 설명과 맞출지 결정이 필요하다.

## 다른 담당 확인

- 승환: `cloud/deploy/entry.py` 런타임 주입에도 공통 migration 키 검사가 필요하다. Fake/온프렘은 거부하지만 AWS 경로에는 아직 검사가 없다. 담당 파일은 수정하지 않았다.
- 서윤: approval_view.preparation_failures를 환경별 준비 불가 사유로 표시한다. 기존 화면은 변경하지 않았다. origin/cloud의 app.py 변경과는 함수 단위로 합친다.
- 생성 역할 api.py는 실제 Groq지만 claude-api 라벨을 유지한다. 별도 이름 결정이 필요하다.

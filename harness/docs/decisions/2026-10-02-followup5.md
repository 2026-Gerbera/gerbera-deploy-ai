# 2026-10-02 후속 수정 5 — 정준우 범위

사용자 후속 수정 5 및 최우선 PR #8 quality 교정 지시를 반영한다. 공유 추가 항목은 사용자 지시로 구현했으며 **야간 추가, 아침 검토 필요**다. 실제 AWS·GitHub push·VM·프로세스 종료 명령은 수행하지 않는다.

1. 환경 릴리스의 `images`는 이전 성공 릴리스와 이번 빌드 이미지를 합친다. `image_sources[tier]`에 release/source/candidate SHA·snapshot·artifact·observation·carried_forward를 기록한다. 새 build의 `ReleaseArtifacts.snapshot`에 이전 산출물을 섞지 않는다. 온프렘 rollback의 RELEASE_ID/SOURCE_SHA도 tier별 출처를 따른다.
2. FAKE HTTPS 저장소에는 FakeAppRepository를 주입한다. 후보/게시 결과는 fake/SIMULATED이며 Git 쓰기를 하지 않는다. 실제 모드 origin/승인/비밀값 검사 차단은 유지한다. 로컬 bare 리허설은 실제 Git fixture를 쓰고 비밀검사만 명시적 통과용 fixture로 주입한다.
3. `RunContext.source_binding: SnapshotBinding | None`은 선택 필드다. prepare 호출자 사전 지정은 거부하고, 실행기가 승인된 사본을 만들 때 채운다. refresh는 이를 바꿀 수 없고 `release_artifacts.snapshot`과 일치해야 한다.
4. `PLATFORM_OUTPUTS.image_repository`(문자열)를 추가한다. codebuild_project_name 등 허용 출력을 FAKE/REAL별로 보존해 다음 prepare에 공급한다. 민감 output은 거부하며, 허용된 ARN 식별자는 비밀값이 아니므로 정확히 보존한다.
5. 생성 번들은 코드 소유 state 버킷과 설정을 선언/변경하지 못한다. S3 plan의 대상이 미확정이면 거부한다. CodeBuild source.buildspec에는 실패 전용 코드 상수만 허용하고 C2 StartBuild가 코드 소유 buildspecOverride를 공급한다. 환경변수 override 이름 4개와 정확한 소스 위치만 허용하는 deployer 정책 설계를 추가했다. IAM은 buildspec의 내용까지 검사하지 못하며 C2의 코드 고정이 필요하다.
6. 생성기와 실행기의 연결은 O1 책임이다. `GenerateInfraInput`은 run_id/directory/layer, `GenerateInfraOutput`은 같은 directory/layer, files={직접 하위 .tf 이름: sha256:해시}, outputs={허용 출력명: [표현식, 타입]}, source를 받는다. O2는 이 계약으로 툴을 구현·등록한다. 조립은 파일 목록·경로·해시·크기를 검증하고 영속 InfraRuntime, 단기 SDK 세션, Analyzer, 최신 승인·잠금 조회를 주입한다. 생성기 누락은 명확한 오류이며 실제 경로에 가짜를 등록하지 않는다. 기본 bootstrap layer=platform, update layer=app; 플랫폼 개선 계획 선택은 추가 협의 대상이다. 이미지 저장소 표현식은 JSON 문자열 리터럴, 기타 출력은 허용된 AWS 속성 참조다.
7. state 부트스트랩 실패는 대체 허용안인 **프로젝트·layer 영속 복구 표식**을 사용한다. local apply 이전에 run/work_dir/local_state_path/plan hash를 남기고, remote 이전 성공 전 실패하면 다른 run도 거부한다. state 내용을 자동 출력/삭제하거나 불명확한 작업을 자동 재개하지 않는다. bucket 생성 증거도 태그 쓰기 전에 남기며 태그 없는 기존 버킷을 자동 인수하지 않는다.
8. 앱 Git은 http.followRedirects=false. 태그 조회용 clone보다 앞서 FetchPolicy의 scheme/host를 검사한다. 저장소 없음/origin 불일치는 git.status=FAILED, phase=repository, code/detail로 기록한다.
9. migrate precheck.expected와 요청한 마지막 migration 버전이 다르면 up을 실행하지 않는다. state 이전 init에는 별도 120초, apply 1200초, 출력 조회 30초를 부여한다.
10. foundation HCL은 참고본이다. 제품은 infra 승인 뒤 SDK로 foundation을 만들며 별도 수동 apply/기반 승인 버튼을 요구하지 않는다. 소스 생성의 fixture/replay/cache/live 출처는 C-18 headline에 별도로 표시한다. 검사기 자체의 source와 구분한다.

잔여 연결·검증은 [후속 수정 5 인계](../guides/O1-followup5-handoff-2026-10-02.md)를 따른다. 공유 스키마는 `make -C harness contracts-update`로 갱신했다. 승인 후 코드 실행과 AI 개발 에이전트의 실제 Terraform 직접 실행 금지는 별개다.

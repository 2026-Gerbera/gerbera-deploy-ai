# 관리 웹 KO/JA 전환

정준우 승인(2026-10-04). 한국어를 기본으로 한국어·일본어 전환을 지원한다.
언어는 query `lang` → `ddak_lang` 쿠키 → ko 순서다. 쿠키는 HttpOnly,
SameSite=Strict, path=/, 30일이며 로컬 관리 웹의 CSRF 쿠키와 같은 Secure 조건을 쓴다.

- 로더는 Jinja 구분자 밖의 표시 문구만 번역한다. 출력 finalize는 정확한 str만 번역하고
  Markup·매크로 HTML은 보존한다. 한국어 데이터 비교식과 저장된 원문은 바꾸지 않는다.
- JSON 번역은 narrative-errors·pipeline-wording의 표시 사전만 대상으로 한다.
  기술 정보·IAM 문장·승인 원문·기존 생성 문장은 번역하지 않는다. JS는 언어별 사전을 쓴다.
- 답변 언어는 별도 `answer_languages` 테이블(ko/ja, 기본 ko)에 저장한다.
  새 준비 요청이 접수된 뒤 라우트가 기록하며, 재사용·거절된 요청은 기록하지 않는다.
  저장 실패는 기록만 남기고 준비를 계속한다. 설정 행·버전·수정 시각은 바꾸지 않는다.
  실행 컨텍스트의 `project_settings` 사본에만 `ai_answer_language`를 주입한다.
  수동 요청은 요청 문맥의 언어를 고정하며, 공용 POST 보안 검사에는 저장 동작이 없다.
  자동 감시는 마지막 저장값, 코드 질문은 질문 요청의 언어를 사용한다.
  한국어 프롬프트는 원문 바이트를 유지하고 일본어는 자유 문장 언어 지시 한 줄만 덧붙인다.
  일본어 지시는 본문에 남은 한국어 출력 지시보다 우선하며 구조·길이 제한은 유지한다.
  생성 출처와 실제 한글 문장이 확인된 경우에만 `韓国語で生成`을 붙인다.
  규칙 기반 요약과 저장소 제거 근거는 표시 사전으로 번역한다.
- 저장소 기준본은 일본어일 때만 캐시 키에 `-ja`를 붙인다.
  한국어 번들·캐시 경로 바이트는 유지하고 두 언어의 기준본을 서로 재사용하지 않는다.
- PR-1 범위는 대시보드·승인·진행·결과와 공통 상태·서술·실시간 문구다.
  PR-2에는 settings, setup, setup_actions, ops, _ops, patch_review, overview,
  form_failure 및 해당 전용 부분 화면의 번역을 남긴다.

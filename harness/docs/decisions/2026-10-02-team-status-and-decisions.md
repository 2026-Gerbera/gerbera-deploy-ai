## 선택지와 장단점

결정 1~11은 사용자가 확정했으므로 여기에는 남은 선택만 둔다(위 "확인 대기" 표).

## 이유

- 1·2·8: 배포할 코드와 배포된 코드를 Git 커밋으로만 가리키게 해서, 승인한 트리와 빌드·배포한 트리가 다를 틈을 없앤다.
- 3·4: 한 환경의 실패가 다른 환경을 멈추지 않게 하고, 비교하지 못한 결과를 "둘 다 같은 코드"로 기록하지 않는다.
- 5: 3일 일정에서 파이프라인 E2E를 먼저 확인하고, LLM 장면은 그 위에 얹는다.
- 6·7: AI는 제안만 하고 실행은 검증·승인 뒤 코드가 한다는 경계를 초기 인프라에도 그대로 적용한다.
- 9: 플랫폼 buildspec을 코드가 소유해야 앱 저장소의 buildspec이나 AI 생성물이 빌드 권한을 넓히지 못한다.

## 반대 의견

- 블루그린: 김준석이 롤링 대신 블루그린을 제안했다. 1차 일정 때문에 롤링을 유지하고 1차 뒤 검토 후보로 남긴다(기록 유지).

## 되돌리는 조건

- 롤링 중 502가 drain 처리 뒤에도 반복되면 블루그린을 다시 검토한다.
- 실제 AWS 부트스트랩에서 SDK 기반 생성이나 state 이전이 실패하면 결정 6의 순서를 다시 본다(사람 사전 적용 전제로 돌아가지는 않는다).
- CodeBuild가 공개 저장소 SHA를 직접 받지 못하는 사실이 확인되면 S3 대체 경로를 기본으로 올린다.

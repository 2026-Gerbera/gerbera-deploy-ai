## 제품 밖 사전 준비

관리 제품이 설치되어 온프렘 프로필로 자동 기동된 WSL, uv >=0.12.20,<0.13, Git·Docker·buildx·bash·jq·SSH, amd64·arm64 실행 지원, 준비된 VM/키 등록이 필요하다. uv와 특권 QEMU 등록은 제품이 하지 않는다. 관리 제품 자동시작 설치기도 이번 범위가 아니다. 필요한 조건이 없으면 검사 결과를 남기고 중단하며 터미널 우회로 성공 처리하지 않는다.

Tailscale·Cloudflare 터널·VM 콘솔은 제품 밖 접속 수단이다. 관리 웹은 해당 PC의 loopback에서 사용한다. 터널 공개 주소는 관리 웹 주소가 아니라 배포 앱의 public_url이다. Claude CLI는 이미 로그인된 경우만 사용한다. 웹에서 로그인할 수 없으므로 터미널 없는 시연에서는 API 제공자와 웹 키 입력을 선택할 수도 있다.

## 입력 순서

1. **프로젝트 설정**: 기존 VM 소유 이름과 같은 프로젝트(시연은 `flaskr-three`)를 선택한다. 저장소 `https://github.com/2026-Gerbera/gerbera-application`, 감시 브랜치 `prod`, 대상 `온프렘`을 저장한다. 처음에는 자동 감지를 끈다. 온프렘 단독이면 cloud_domain은 비워 둔다. 같은 저장소·브랜치의 중복 자동 감지가 없어야 한다.
2. **초기 연결 설정 → 역할/모델**: 생성·판단 provider와 모델을 고른다. Claude를 쓰면 `claude-sonnet-5-5`, 추론 low, WSL 첫 호출이 느린 환경은 AI 제한 시간 60~90초를 지정한다. API 키 입력 또는 기존 CLI 상태 확인 후 역할별 연결 테스트한다. 키 등록과 실제 연결 성공을 구별한다.
3. **빌드/작성자**: 빌드는 로컬 Docker, 이미지 저장소는 `2026gerbera/flaskr`. 빌더 이름은 비워 제품 전용 이름을 쓰거나 준비된 빌더 이름을 입력한다. 커밋 작성자 이름·이메일에 운영자 본인 신원을 저장한다.
4. **앱 저장소 push 인증**: 현재 저장소의 토큰을 password 입력에 저장한다. 토큰은 다시 보이지 않는다. ai-prod·main·deployed/* 갱신 권한이 필요하다. 저장소 권한 검사를 누른다. 인증 오류로 감시가 이미 멈췄다면 토큰 교체 후 자동 감지를 껐다 켠다. 검사는 dry-run이며 실제 정책/태그 갱신 성공을 미리 보장하지 않는다.
5. **온프렘 인벤토리**: tier별 VM 호스트·SSH 사용자·기존 키 경로·호스트 지문, 플랫폼, public_url, 포트·볼륨을 JSON 폼에 입력한다. web은 192.168.10.4/server1, was는 192.168.10.2/server2, 기존 DB는 192.168.10.3/server3인 준비 환경을 확인해 사용한다. 키 내용·DB 비밀번호를 JSON에 넣지 않는다. nginx ready는 기본 `/nginx-health`/8080이며 실제 이미지와 맞춰 저장한다. 자동 3티어 DB 계획은 미완이므로 이미 준비한 DB를 쓰는 web/was 앱 계획으로 시작한다.
6. **환경 값**: 공개 값 APP_ENV는 WAS public_env에 앱이 요구하는 값으로 입력한다. 이 시연에서는 `onprem`이다. MIGRATE_MODE처럼 기본값 있는 선택 키는 필수 입력이 아니다. RELEASE_ID/SOURCE_SHA는 제품이 채운다. 필요한 DATABASE_URL 등은 실행 환경 비밀값 폼에, 기존 DB 마이그레이션 URL은 별도 폼에 넣는다. 같은 키를 public_env와 비밀값 양쪽에 넣지 않는다. 외부 env_file 덮어쓰기 경고가 있으면 제품 등록 경로로 정리한 뒤 검사한다.
7. **Docker Hub 인증**: 사용자명과 push 토큰을 입력한다. 저장 후 토큰은 보이지 않고 제품 전용 DOCKER_CONFIG만 사용한다. 로그인 성공과 조직 저장소 push 권한은 다를 수 있다.
8. **필요 도구 설치**: 계획의 버전·SHA·빌더 이름을 확인하고 버튼을 누른다. gitleaks 검증 설치와 기본 제품 빌더 준비만 수행한다. uv는 검사만, QEMU 등록은 하지 않는다. 빌드 도구 검사에서 각 항목의 상세 상태를 확인한다. 미지원 플랫폼/uv 버전 오류는 사전 환경 담당자가 해결하기 전까지 진행하지 않는다.
9. **연결 검사**: 온프렘 환경·앱 저장소·빌드 도구·AI를 검사한다. 오류 메시지와 설정 덮어쓰기 경고를 확인한다. `미확인`을 `성공`으로 해석하지 않는다. DB 잔재가 있으면 DB 준비 페이지에서 이동할 표·백업 DB·계정 계획을 확인한 뒤 승인한다. DB 소유권이 다르면 중단한다(승계 기록은 설계 단계). WEB/WAS 소유권만 승인 이전이 지원된다.

## v1 → v2 → v1 왕복

1. 자동 감지가 꺼진 상태에서 대시보드 ‘직접 배포 준비’에 준비된 태그 `v1`을 입력한다. 원본 SHA·계획·준비 경고·패치/판단 근거를 보고 승인한다. 진행 표시가 움직이며 단계가 끝나는지 확인한다. 결과에서 공개 주소와 `/version`, health·base smoke 및 이미지 digest를 확인한다.
2. 프로젝트 설정에서 자동 감지를 켠다. 저장소에 성공 기록이 없는 첫 기동은 기존 HEAD를 바로 요청할 수 있다. 준비된 v2 변경 PR을 저장소 웹에서 prod에 merge한다. 이는 개발자 입력이며 배포 운영자의 셸 작업은 없다. 승인 대기 동안 추가 merge를 하지 않는다.
3. 새 v2 run 하나만 생겼는지 확인하고 원본 SHA·step·새 env 키/값 필요·검사 결과를 검토해 승인한다. 결과 페이지에서 v2의 이미지·박스, base+v2 smoke, 실제 digest를 확인한다. 강제 3분 성공이나 미확인 단계 성공을 주장하지 않는다.
4. 자동 감지를 끄고 ‘직접 배포 준비’에 `v1`을 다시 입력해 승인한다. v1 복귀는 base만 검사하고 공개 `/version`과 이미지 기록이 해당 후보를 가리키는지 확인한다. 코드 복귀는 DB 역마이그레이션이 아니다. 이전 패치 손실 관문에 걸리면 우회하지 말고 원본/패치 차이를 기록한다.
5. 각 결과의 단계별 elapsed_ms와 실행 시작/완료 시간을 보관한다. 승인 대기 시간은 따로 본다. 실패하면 실패 환경만 복구됐는지 결과를 확인한다. NEEDS_HUMAN 잠금은 실제 상태 확인 후 대시보드에서 사유를 입력해 해제한다. 제품 잠금 해제가 인프라 복구 성공을 뜻하지 않는다.

## 막혔을 때

대시보드 준비 경고 → 해당 run 진행/결과의 phase·code·detail 순서로 확인한다. 실행 파일은 제품 상태 폴더의 runs/<run_id>/{events.jsonl,error.json,plan.json,facts.json,release.json}이며 화면/기록의 가려진 내용만 공유한다. 토큰·env·개인키 파일 원문은 열거나 공유하지 않는다.

도구 설치 실패는 초기 연결 설정의 상세 검사와 설치 기록을 확인한다. SHA 불일치는 설치하지 않는다. 부분 준비 뒤 플랫폼이 없으면 설치 성공을 전체 준비 성공으로 표시하지 않는다. 이전 기록은 유지된다.

**현재 확인:** `core/redact.py`의 `MAX_LEN=4096`은 문자열 단위 한도다. `gateway._safe_data()`는 키/패턴 가림과 길이 절단을 수행하고, `call_ai`가 instruction/data를 처리한다. 전체 번들을 JSON으로 넣으면 중간에서 잘릴 수 있다. 파일 수 제한만으로는 해결되지 않는다. 이 통합본의 생성기 본문은 최초 생성 1회이며, cloud 스레드 교정 경로를 가져오거나 수정하지 않았다.

**제안:** 4,096자를 유지하고, 생성 툴 내부의 코드가 오류 관련 파일/블록을 선택한다. provider나 AI가 입력 예산·선택 범위를 정하지 않는다.

1. **입력 후보 선별.** 현재 생성 번들의 허용된 기존 `.tf` 파일만 받는다. 상대 경로·일반 파일·UTF-8·크기·HCL 구문을 먼저 검사한다. 링크/경로 탈출/중복 파일은 거부한다. tfstate·plan 원문·환경 파일·인증 정보·실행 로그 원문은 후보가 아니다. 여기서 통과해야 할 것은 전송용 형식/비밀값 검사이며, 고치려는 배포 정책 검사까지 이미 합격해야 한다는 뜻은 아니다.
2. **진단 최소화.** 검사기가 만든 규칙 ID·파일·리소스 주소·필드 이름·고정 설명만 전송한다. raw 예외/CLI stdout은 보내지 않는다. 참조 의존성도 검사된 주소·출력 이름의 최소 목록만 포함한다. 비밀값 검사 통과만으로 모든 내용이 공개라고 간주하지 않는다. 비밀을 담을 수 있는 default/user_data/environment/secret_string/인증 필드는 제외하고, 상수 값은 승인된 공개 설정 또는 코드의 enum 허용 목록과 일치하는 것만 허용한다.
3. **분할과 초과 처리.** 관련 파일 하나가 들어가면 파일 단위, 아니면 파서가 찾은 완전한 HCL 블록 단위로 나눈다. 임의의 N번째 문자에서 자르지 않는다. HCL 구문 자체가 틀려 안전하게 나눌 수 없거나 블록 하나가 너무 크면 원문을 전송하지 않고 `AI_OUTPUT_INVALID`로 교정을 중단한다. 새 번들 재생성은 별도 요청으로 둔다. 다른 파일은 코드가 보관하고 교정 요청에 반복해 넣지 않는다.

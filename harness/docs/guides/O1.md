# O1 런타임 연결

실행 진입점은 `ddak.executor.service.DeploymentService`다. `Executor`만 직접 호출하면
승인·프로젝트 잠금·영속 기록이 연결되지 않으므로 제품 진입점으로 쓰지 않는다.
웹 기동 시 `app.state.deployment`에 동일 서비스가 들어간다. 승인 화면·인증·CSRF·SSE
HTTP 라우트는 C3 구현이며, 이 내부 Python API를 인증 없이 외부에 노출하지 않는다.

```python
run_id = service.prepare(
    plan,
    context,
    source_path,
    patch=proposed_diff,
    facts_reader=recompute_facts,
    subjects={"infra": plan_sha256},
)
view = service.approval_view(run_id)  # diff, 계획, 대상별 해시를 한 화면에서 표시
service.approve(run_id, approver="operator")  # 실제 사용자 승인 시에만 호출
service.start(run_id)  # 브라우저 연결 종료와 독립적인 task
result = await service.wait(run_id)
events = service.events(run_id, after=last_seq)
```

인프라 변경이 없으면 `subjects`를 생략한다. `prepare`는 임시 사본 검사만 하고,
실제 사용자 승인 이후 `start`가 빌드 사본을 만든다. 승인 호출을 자동 승인 로직으로 쓰지 않는다.

## 팀별 연결점

| 담당 | 입력/결과 |
|---|---|
| O2 | 검증된 `Plan`, `RunContext`, 소스 경로, `facts_reader(Path) -> sha256`. `plan_digest`는 `plan_hash` 자체를 제외한 정규 JSON 해시다. 소스 해시는 `core.snapshots.file_manifest` + `digest_json`을 공유한다. |
| O3 | UTF-8 unified diff(`a/`, `b/`, 일반 파일), health/smoke/compare 출력의 명시적 `passed: bool`, WAS 마이그레이션 러너. |
| C2 | 빌드 출력의 `release_artifacts: ReleaseArtifacts`. 실제 빌드 입력은 `ctx.build_source`. CD 결과의 `observation`은 config image ID가 아닌 플랫폼 manifest digest다. AWS provider 구현은 별도다. |
| C1 | 승인할 Terraform plan 해시와 `refresh(step, output, ctx) -> RunContext`. apply 뒤 허용된 출력으로 새 컨텍스트를 반환해야 다음 신호가 열린다. 연결이 없으면 apply 전에 거부한다. |
| C3 | 위 승인/실행 API, `subscribe(run_id, callback)` 및 `events(run_id, after=seq)`, `store.run`/`store.environments`. 화면 콜백은 큐에 이벤트를 넣고 즉시 반환한다. |

O1 공통 CD 등록 툴은 `inject_env_config`, `prepare_db`, `deploy_tier`, `rollback_tier`다.
입력에는 `run_id`, `target`, `lock_token`, tier 작업은 `tier`가 있다. 키·migration ID
목록 이외의 실제 값은 컨텍스트/호스트 파일에서 읽는다. 나머지 팀 툴이 미등록이면
`prepare`가 실행 전에 실패한다. 제품 실행에서 가짜 구현으로 자동 대체하지 않는다.

## 로컬과 기록

- Docker CLI·buildx와 로컬 Unix 소켓을 사용한다. SSH/VM은 이번 구현 범위 밖이다.
- `ctx.platform.onprem.tiers`의 `name`, `platform`, `ports`, `network`, `volumes`,
  `env_file`을 사용한다. 상세 허용값은 `cd/providers/onprem.py`의 입력 모델에 있다.
  공개 설정은 `public_env`로 주입하고 비밀값은 호스트 env 파일에만 둔다.
- `ctx.images`는 digest 고정 참조다. 이미지와 플랫폼 manifest 검증이 끝나야 기존
  컨테이너를 멈춘다. 소유 프로젝트/tier 라벨이 다른 컨테이너는 건드리지 않는다.
- `var/ddak.sqlite`가 실행·승인·환경별 성공 기록의 기준이다. `var/runs/<run_id>/`에는
  계획, diff, 빌드 사본, 가린 컨텍스트, JSONL 이벤트, 최종 릴리스 export가 있다.
- 최초 실배포는 `mode=bootstrap`으로 성공 기록을 만든다. 실환경 update는 해당
  환경의 실제 성공 기록이 있어야 한다. fixture 기록은 실환경 복구 기준으로 쓰지 않는다.
- 배포 결과가 달라지면 `DIVERGED`, 복구 실패·종료 미확인 타임아웃이면 `NEEDS_HUMAN`으로
  다음 실행을 막는다. TTL 만료만으로 잠금을 빼앗지 않는다. DB/인프라는 역변환하지 않는다.
- 롤백 제한 시간은 등록된 툴의 tier별 제한 시간을 합산한다. 잠금 갱신의 일시적 SQLite
  경합은 재시도하고, 연속 3회 실패하거나 잠금이 무효이면 실행을 중단하고 잠금을 남긴다.
- 한 상태 디렉토리에는 컨트롤러 하나만 실행한다. 재시작 시 실행 중 작업은 `NEEDS_HUMAN`,
  미실행 계획은 `CANCELLED`로 표시하고 새 run으로 준비한다. 자동 재개는 없다.
- 실패 복구 확인은 실제 Docker 상태와 DB 이력을 대조해야 한다. 일반 운영 잠금 강제 해제나
  임의 DB 초기화 명령은 제공하지 않는다. 리허설은 전용 데모 상태/자원으로 분리한다.

## 검증 범위

`make -C harness ci`는 외부 서비스 없는 검사다. `make -C harness demo`의 fixture
결과는 실제 AWS·CodeBuild·AI 결과가 아니다. Docker 테스트는 테스트 전용 HTTP 앱과
일회성 마이그레이션 러너를 사용하므로 실제 flaskr/MySQL 스키마 검증을 대신하지 않는다.
3분 기준은 팀 통합 뒤 코드 변경부터 양쪽 검증 완료까지 따로 실측한다.

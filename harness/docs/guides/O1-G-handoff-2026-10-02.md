## C3 연결 API

```python
async def request_deployment(
    self,
    project: str,
    *,
    targets: Literal["onprem", "cloud", "both"] | None = None,
    ref: str | None = None,
) -> str: ...
```

실제 호출 예: `await service.request_deployment("demo", targets="both", ref="v1")`.
repo_url은 저장된 프로젝트 설정을 사용한다. targets=None은 **요청 생성 시** default_targets를 선택한다.
ref=None은 watch_branch(기본 prod), 그 외에는 그 감시 브랜치 또는 v* 태그만 허용한다.
태그는 `refs/tags/v1`로 정규화하며 접두사 포함 200자 제한이다. 임의 SHA와 설정된 감시 브랜치가 아닌 일반 브랜치는 거부한다.
따라서 watch_branch=prod일 때 main/ai-prod는 거부하지만 main을 감시 브랜치로 설정한 경우 main은 허용한다.

반환값은 run_id 문자열이다. 계획/준비 실패도 반환한 run_id의 `get_run`에서 확인한다.
그 결과는 `FAILED_BEFORE_DEPLOY`와 `result.phase/code/detail/missing_tool`(있을 때)을 가진다.
입력 오류·저장소 설정 누락·planning_flow 미주입은 DdakToolError다. 트리거는 manual이며 자동 감시는 auto다.
승인 대기는 `approval_view` → `approve(run_id, approver=...)` → `start` → `wait`로 진행한다.
화면·HTTP 라우트는 수정하지 않았다. 인증·CSRF·권한 검사는 기존 C3 경계를 유지한다.

## 재시작과 운영 연결

- `prepared_runs`는 0600 SQLite에 실행 입력 원본과 승인 해시를 저장한다. 표시용 context.json으로 실행 입력을 복원하지 않는다.
- 커스텀 facts_reader는 재기동 시 `DeploymentService(..., facts_readers={저장된키: 함수})`로 같은 함수를 주입한다. 기본 source manifest 함수는 자동 복원한다. 함수 이름을 임의 import하지 않는다.
- 인벤토리는 `DDAK_ONPREM_INVENTORY` 경로로 읽어 platform.onprem에 넣는다. 클라우드만 선택했을 때는 읽지 않는다.
- 후속3에서 app.create가 프로젝트 repo_url로 제품 전용 checkout factory를 주입하도록 연결했다. 승인 화면 URL과 실제 origin fetch/push URL이 같아야 하며 재시작에도 같은 checkout을 연결한다. Git 실행 사용자 신원·인증·원격 권한은 실행 호스트 사전 준비 항목이다. 실제 GitHub push 검증은 하지 않았다.
- C1 InfraBinding은 파일·세션 함수를 가진 메모리 연결이다. 승인 입력은 복원되지만 controller 재기동 뒤 실제 인프라 실행에는 기존 승인 plan을 가리키는 binding 재주입이 필요하다. 승인 뒤 generate_infra 재생성은 금지한다.
- 구형 미저장 pending은 CANCELLED, 실행 중 재시작은 NEEDS_HUMAN이다. 기존 배포를 자동 재개하지 않는다.

## 담당자 요청

제품은 `validate_infra` → `plan_infra` → 한 화면의 infra 승인 → foundation(state bucket + app/build 권한 경계) → platform apply 순서로 실행합니다. bucket이 없으면 local backend plan을 승인한 뒤 코드가 SDK로 bucket을 만들고 platform local apply 후 remote backend로 state를 이전합니다. 사람이 미리 foundation/platform을 apply하는 전제는 폐기합니다. 사람의 사전 준비는 AWS 자격증명과 도메인 구매입니다. AI 개발 에이전트는 Terraform을 직접 실행하지 않으며, 승인 뒤 제품 코드가 실행하는 경로와 구분합니다. 실제 생성기의 O2 연결은 아직 미완이고 AWS 전체 완료를 의미하지 않습니다.

💭 v2 기능은 미정이며 로그인은 후보입니다. 정준우의 10/2 검증은 1차 Flask 기본 앱에 이미지·박스를 추가한 파이프라인 E2E, 2차 실제 로직의 LLM 분석·패치·인프라 생성 검증으로 나눕니다. 1차 결과로 실제 LLM·AWS 전체 완료를 주장하지 않습니다.

| 담당 | 요청 |
|---|---|
| 서윤(C3) | 설정 저장은 공개 `save_project_settings(..., expected_version=읽은버전)` 사용. 시작 버튼/채팅은 위 request_deployment 호출 후 run 상태 확인, 승인 화면은 approval_view. 직접 store 접근 교체. FAILED_VERIFY/비교 불가와 main 보류 표시 |
| 준석(O2) | watch.py standalone 기본 main→prod 정정. 앱 조립부는 저장된 project_settings의 watch_branch를 Watcher에 공급 중이며 auto_detect 취합을 확인. 계획 결과 source_sha 제공. APP_ENV/MIGRATE_MODE 기본값을 필수 외부 주입 키와 구분. generate_infra의 번들 출력·C1 InfraBinding 조립 계약 합의. 새 앱 DB 이름/계정/ensure_app_database 결정 |
| 승환(C2) | build_image 등록, sourceVersion=candidate_sha, 빌드 commit SHA·이미지 라벨·ReleaseArtifacts(승인 snapshot/index/platform digest) 반환. sync_env_to_cloud/push_image 등록 확인 |
| 민영(O3) | compare_env_results/tool.py 및 smoke_test 등록. 비동등은 passed=False, 도구 오류는 예외로 구분. 패치는 Git 확장 메타 없이 hunk별 ---/+++ 헤더 필요(파일별 하나의 hunk로 정규화 권장). 재사용 패치가 새 prod와 안 맞으면 재제안 |
| 정준우(O1 운영) | 프로젝트 저장소 설정 및 인벤토리 경로 지정. 앱 checkout/factory는 ddak.app이 연결(후속3), 수동 repositories 매핑 불필요. 기존 flaskr DB/볼륨 보존·새 DB 이름은 결정 전 생성하지 않음 |

## 미등록 툴과 리허설 범위

리허설이 실제 계획에서 요구한 미등록 툴은 [roundtrip.json](../benchmarks/2026-10-02-work-g/roundtrip.json)의
`required_pipeline_missing`을 기준으로 한다. 전체 registry 누락은 `missing_real_tools`, 이미 실행기/스크립트로
제공하는 항목은 `implemented_outside_registry`로 분리했다. 테스트에서는 외부 동작을 전용 fake registry로
대체했으며 src에 가짜 툴을 등록하지 않았다.

이 시험은 Flask 서버 실행·Docker 이미지 빌드·AWS 배포·실제 LLM 품질·사람 승인 대기 시간을 입증하지 않는다.
`source=fake` 시간은 로컬 Git과 컨트롤러 성능 참고값이며 현장 3분 보장 근거가 아니다.
G5 연결 회귀도 binding 조회를 대체하고 fake validate/plan 결과로 승인 해시 연결을 검사했다.
실제 Terraform plan을 실행한 통합 검증으로 해석하면 안 된다.

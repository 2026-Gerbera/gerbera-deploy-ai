# C3 클라우드 검증 및 관리 페이지 구현 가이드

## 1. 역할

- 담당: 양서윤
- 역할 코드: C3
- 담당 영역: 클라우드 배포 결과 검증, 결과 보고, FastAPI 관리 페이지

한 줄 요약:

> 클라우드에 배포된 결과가 정상인지 검증하고, 사용자가 설정·승인·진행 상황·결과를
> 확인할 수 있는 관리 페이지를 제공한다.

## 2. 구현 범위

### 클라우드 배포 검증

- ECS 실행 태스크와 ALB Target Group 상태 확인
- ECS가 실제 실행 중인 이미지 digest 확인
- 애플리케이션 `/health/ready`, `/version` 응답 확인
- 실행 ID와 예상 이미지 platform digest 비교

### TLS/HTTPS 검증

- DNS 연결
- 인증서 체인과 호스트명
- TLS 1.2/1.3 사용 여부
- 인증서 발급자와 만료 기간
- ACM 인증서와 ALB 연결 상태
- ALB 80/443 listener와 보안 정책
- HTTP에서 HTTPS로의 301 redirect
- HSTS 헤더

### 결과 보고

- 클라우드와 온프레미스 검증 결과 취합
- 코드 규칙에 따른 성공/실패 판정
- 이미지 index digest와 platform digest 표시
- 설정 및 배포 산출물 누락 감지
- AI를 이용한 사용자용 결과 설명 요약

최종 성공 여부는 AI가 아니라 결정적인 코드 규칙으로 판정한다.

### FastAPI 관리 페이지

- 프로젝트 대시보드
- 도메인 및 DNS 설정
- 패치·인프라·배포 통합 승인
- SSE 기반 실시간 진행 상황 및 재접속 replay
- 최종 배포 결과
- 승인된 패치 다운로드
- CSRF, Host, Origin 검증

## 4. CSP별 현재 상태

| Provider | 모듈 분리 | 실제 배포 | Health/TLS |
|---|---:|---:|---:|
| AWS | 완료 | C2 구현 필요 | C3 구현 완료 |
| GCP | 완료 | 미구현 | 미구현 |
| Azure | 완료 | 미구현 | 미구현 |
| On-premise | 기존 코드 유지 | O팀 담당 | O팀 담당 |

현재 실제 클라우드 실행의 기본 provider는 AWS다. GCP와 Azure는 공통 인터페이스를 구현하는
파일까지 분리했지만 실제 API 호출은 구현하지 않았다. 미구현 provider를 직접 선택하면 AWS
코드로 대신 실행하지 않고 `CONFIG_INVALID` 오류를 반환한다.

공식 CSP 선택 설정은 아직 공통 계약에 없다. `cloud_provider()` resolver는 준비되어 있지만
실행기 dispatch에 GCP/Azure 선택값을 연결하려면 팀 차원의 계약 합의가 필요하다.

## 5. AI 사용 및 보안 원칙

AI는 배포를 직접 실행하지 않는다.

```text
AI가 공개 설정 초안 제안
→ 코드 기반 검증
→ 사용자 승인
→ 일반 코드가 provider 선택
→ 배포 및 검증 실행
```

AI가 제안할 수 있는 값:

- 포트, CPU, 메모리, 컨테이너 수(첫 배포)
- 공개 환경변수
- 배포 설정 초안

AI에 전달하면 안 되는 값:

- AWS/GCP/Azure 자격증명
- API 키와 DB 비밀번호
- Docker Hub 토큰
- Secret 원문

비밀값은 AWS Secrets Manager, GCP Secret Manager, Azure Key Vault 같은 비밀 저장소에 두고
provider에는 참조만 전달해야 한다.

## 6. 팀 연동 사항

### C1: 클라우드 인프라/TLS 구성

C3의 AWS 검증에는 Terraform 출력으로 다음 값이 필요하다.

- AWS region
- ECS cluster와 service
- ALB ARN과 DNS 이름
- Target Group ARN
- ACM certificate ARN
- HTTP/HTTPS listener ARN

C3는 해당 값을 읽기 전용으로 사용한다. Terraform state 원문은 읽거나 파싱하지 않는다.

### C2: 빌드 및 클라우드 배포

C3 검증이 정상적으로 작동하려면 실행 컨텍스트에 다음 정보가 기록되어야 한다.

- 배포 이미지 index digest
- 플랫폼별 digest
- 이전 release 정보
- 배포 tier
- ECS service에 적용한 이미지

AWS provider의 `deploy`, `rollback`, `migrate_db`, `inject_config`는 C2 구현 범위다.

### O팀: 온프레미스

- 이번 작업에서는 `src/ddak/onprem/`을 수정하지 않았다.
- 최종 결과 보고서는 온프레미스 검증 결과도 공통 계약으로 입력받는다.
- 환경 간 비교를 위해 이미지와 검증 결과 형식을 공통 계약에 맞춰야 한다.

### 실행기 및 공통 계약 담당

- AWS/GCP/Azure를 선택하는 공식 설정값과 저장 위치를 결정해야 한다.
- CSP 선택은 AI가 아니라 승인된 설정과 코드가 결정해야 한다.
- 공식 선택 계약이 정해지기 전까지 클라우드 기본 실행은 AWS다.

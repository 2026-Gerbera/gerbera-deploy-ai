## 바로 사용하는 순서

1. 저장소 의존성·Docker 엔진·SSH 키를 준비하고 로컬 컨트롤러를 `make -C harness onprem-run`으로 한 번 기동한다. Claude CLI 로그인은 제품 밖에서 사용자가 완료해야 한다.
2. 대시보드의 프로젝트 설정에서 프로젝트 이름, 저장소 URL, prod, onprem, 자동 감시를 저장한다. 같은 저장소·브랜치 중복 감시는 거부된다.
3. **초기 연결 설정(`/setup?project=...`)**에서 생성/판단 provider·모델, 로컬 빌드, 이미지 저장소 `2026gerbera/flaskr`를 고른다. 키는 password 필드로 저장하며 이후 표시하지 않는다. 환경변수를 export할 필요는 없다.
4. 같은 페이지에서 빌드 준비 계획을 승인하고 Docker Hub 로그인 입력을 한다. 설치·인증 상태 확인은 AI 호출이 없고, 연결 테스트는 선택한 provider에 최소 비용 호출을 한다.
5. 온프렘 JSON에 tier별 호스트·SSH 사용자·키 **경로**·지문, public_url, 준비 경로·공개 환경 값을 입력한다. 제품이 인벤토리를 검증·저장한다. WAS env는 제품 private 디렉토리를 사용한다.
6. 기존 DB는 실행 환경 입력에서 앱 `DATABASE_URL`, **별도 마이그레이션 입력**에서 migrator URL을 넣는다. migrator URL은 migration.env에만 저장한다. 새 앱 DB/계정 준비는 `/setup/actions`에서 이름·현재 테이블 요약을 확인하고 승인한다. 신규 암호와 분리된 URL은 제품이 만든다.
7. 필수 연결을 검사한다. 빨강 상태는 계획·승인·실행을 차단한다. 설정이나 키가 바뀌면 기존 초록을 재사용하지 않는다. 회색은 미확인이며 실제 준비 단계의 필수 검사는 별도로 유지된다.
8. AI 코드 수정 ON → 예시 하드코딩 변경을 prod PR로 merge → 준비 결과/검사 메타 확인 → 승인 → 실행·기록을 확인한다. 데모 변경 파일은 `fix11-demo-hardcoding.patch`와 설명 문서를 참고한다.

준비 실패/설정 누락은 웹에서 수정 후 `/ops`의 현재 HEAD 계획 요청으로 재실행한다. 잠금 해제는 기존 `/ops` 기능이다. 이미 성공한 앱 DB를 비우기 위한 기능으로 DB 준비 화면을 사용하지 않는다.

## DB와 소유권의 남은 제약

- **설계 결정 완료·구현 후속: DB 소유 라벨 변경.** Docker 라벨은 재생성 없이 바꿀 수 없고 기존 결정은 DB 컨테이너/볼륨 재생성을 금지한다. DB는 별도 승계 원장으로 관리 소유권만 이전하는 설계를 선택했다. `O1-db-ownership-succession-design-2026-10-03.md`에 관측/승인/구 소유자 차단/복구 조건을 기록했다. 원장 실행 구현 전까지 DB 이전은 거부하며 WEB/WAS만 지원한다.
- DB 준비는 이미 동작하는 owned MySQL 컨테이너가 있어야 한다. VM/엔진/DB 컨테이너를 새로 설치하는 기능까지 완료됐다는 뜻은 아니다. 최초 컨테이너 생성은 기존 3티어 배포 경로다.
- 기존 계정의 암호를 제품 Vault가 모르면 암호를 임의 교체하지 않는다. 새 계정 이름을 선택하거나 기존 앱/마이그레이션 URL을 설정한다.
- 교차 DB RENAME이 안전하지 않은 FK·trigger·view·비 InnoDB 관측은 중단한다. 준비 중 상태가 바뀌거나 부분 실패하면 NEEDS_HUMAN이다. 성공은 준비 완료일 뿐 배포/헬스 성공 기록을 만들지 않는다.

## AI provider 추가 방법과 호환성

`core/ai/providers/README.md`의 ProviderSpec을 따른다. 구현 파일 하나와 `register_provider(...)` 한 줄에 id/표시명/종류/지원 역할/인증/기본 모델·목록/factory/status/test를 등록한다. 웹과 생성·판단 선택은 같은 등록부를 쓴다. 새 SDK 의존성은 없다.

`api.py`는 공통 인터페이스/호환 export이고 Groq 본문은 `groq_api.py`, Claude Messages는 `anthropic_api.py`다. 기존 `DDAK_LLM_BACKEND=api`와 잘못 이름 붙였던 `AnthropicApiProvider` alias는 **Groq 경로를 유지**해 기존 키가 다른 회사로 전송되지 않게 했다. 새 설정은 `claude-api`/`groq`를 명시적으로 고른다. 이 legacy alias 제거는 별도 호환성 변경이다.

AGENTS 수정 제안(직접 수정하지 않음): “생성·판단 provider는 코드 등록부와 저장 설정으로 선택한다. Claude CLI는 본인 로컬 loopback만, Claude API/Groq는 별도 선택이며 키는 관리자 페이지에서 저장한다. legacy api는 Groq 호환 별칭이다.” 이미지 행에는 관리형 로컬 빌드 백엔드와 승인된 도구 준비를 추가한다.

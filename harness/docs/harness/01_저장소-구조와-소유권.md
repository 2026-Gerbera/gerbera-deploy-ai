### 구조 원칙 (💭, devpi-guardian 통합 실패의 교훈 + 앱 1개)

- 모듈 경계를 담당 경계에 맞춥니다. 모듈끼리 import하지 않습니다(import-linter 계약 3).
- 툴은 1툴 1디렉토리입니다. `ddak.app`이 `tools/` 아래를 **이름순으로 자동 등록**하므로 등록 목록 파일을 여럿이 고치지 않습니다.
- 툴 메타정보는 `registry.py` 카탈로그 한 곳에 있습니다(40개, 첫날 한 번에 작성). 이후에는 계약 변경 PR로만 고칩니다. 실행기·계획 검증·관리 웹은 카탈로그와 레지스트리 이름 조회만 쓰고 툴 모듈을 import하지 않습니다(계약 4).
- 번호 붙은 공유 파일(migration 001 등)을 여러 명이 동시에 만들지 않습니다.
- `apps/sample-app`은 패키지에 넣지 않습니다. 배포 대상이고 외부 코드(flaskr) 원형과 데모용 개발값을 그대로 두려고 ruff와 CI에서 제외합니다.
- 💭 대안 [I-32]: 담당 경계를 더 강하게 하려면 uv workspace 패키지(`ddak_core`, `ddak_plan`, …, 조립 `ddak_app`)로 나눌 수 있습니다. 하네스 기본값은 단일 패키지(설정·lock이 단순).
- CD는 툴마다 local/cloud 어댑터를 두는 대신 **공통 인터페이스 + provider 모듈**입니다(✅ 9/30, [결정 기록](../decisions/2026-09-30-cd-provider-structure.md)). cd 툴(`tool.py`)은 `select_provider(target, mode)`로 provider를 고르고 인터페이스 함수(deploy·rollback·health_check·migrate_db·inject_config·ensure_tls)를 부릅니다. 다른 모듈(plan·infra·ci·verify)은 기존 어댑터 규약(`core/adapters.py`)을 씁니다.

## 2. 툴 40개 모듈 배치·step 층·담당

- 모듈은 💭 레지스트리 트리 고려안(9/30, [결정 기록](../decisions/2026-09-30-cd-provider-structure.md))입니다. 옛 배치(`plan_validate`/`build_deploy`/`verify_report`, [docs/18](../../../docs/18_팀-합의요청-MCP-구조.md) B-3)를 대체합니다. P0/P1/P2는 [04 툴 카탈로그](../../../single-app/docs/04_툴-카탈로그.md)가 정합니다(최종 목록은 팀 결정).
- step 층: 내장(계획에 안 나옴) / 필수(AI가 뺄 수 없음) / 조건부(규칙 조건이 참일 때만 뺄 수 있음) / 선택(AI 자유) / 계획 밖. 카탈로그 값은 툴의 기본값이고 step 카탈로그가 대상별로 덮어씁니다.
- 플래그: ai=uses_ai, ro=read_only, de=destructive, lock=requires_lock, ok=requires_approval. 담당은 공통 / local / cloud 순서.

## 3. 역할별 소유 디렉토리 (CODEOWNERS, 💭)

실제 파일은 `.github/CODEOWNERS`입니다(자리표시자 옆에 실명 주석). GitHub 규칙:

- **마지막으로 매칭된 줄이 이깁니다.** 일반 규칙을 위에, 구체 규칙을 아래에 둡니다.
- **한 줄에 여러 명을 적으면 그중 1명 승인으로 충족됩니다.**
- **PR 작성자 본인의 승인은 인정되지 않습니다.** 그래서 줄마다 주 담당과 짝(buddy)을 함께 적습니다. 짝은 💭 C1↔C2, C3↔O3, O1↔O2이고, 하네스·계약 파일은 @TL과 O1이 짝입니다. 테크 리드는 공식 지정이 없으므로 @TL을 누구로 둘지 먼저 정합니다 [I-30].
- 자리표시자를 실제 GitHub ID로 바꾸기 전에는 main 보호를 켜지 않습니다. 쓰기 권한이 없는 사람이 적힌 줄은 조용히 무시됩니다.
- CODEOWNERS를 push한 뒤 GitHub 파일 화면에 오류 표시가 없는지 확인합니다. 특히 `**` 패턴을 확인합니다.
- 두 명 승인을 강제할 수 없으므로 계약 변경 때 소비자 담당 멘션은 사회적 규칙으로 둡니다([03](03_깃-규칙과-AI-컨트리뷰터-차단.md) E-2).

## 4. 명령 표준 (단일 진입점)

- 모든 명령의 실제 구현은 `scripts/dev.py`(표준 라이브러리)에 있습니다. `Makefile`은 이를 부르는 얇은 래퍼입니다.
- 문서, CI, 가이드는 `make <타깃>`만 가리킵니다. Windows 사용자는 `python scripts/dev.py <작업>`을 씁니다.
- `setup`만 시스템 python3로 실행합니다(uv 설치 전에도 동작, python 3.9 이상). 나머지는 uv 환경에서 실행합니다.
- 담당자가 아직 구현하지 않은 작업은 "미구현(담당 X)"을 출력하고 종료 코드 3을 냅니다.
- make 변수: `ARGS`(test 인자), `ALL=1`(type 전체), `CLOUD=1`(demo-reset), `FULL=1`(attribution 전체 이력).

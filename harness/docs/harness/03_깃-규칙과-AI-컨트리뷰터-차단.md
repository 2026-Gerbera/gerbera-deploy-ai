# Git·CI 최소 운영 기준

2026-09-30 사용자 결정: 3일 개발 일정에 맞춰 협업 규칙을 최소화합니다. 이전 문서의 E-1~E-6, 이메일 허용목록, 필수 PR 승인, main 직접 push 금지 지침은 이 기준으로 대체합니다.

> 2026-10-01 갱신(✅ 팀 결정): main에 직접 push하지 않습니다. 각자 브랜치 + PR로 올리고 merge는 사람만 합니다. 아래 "제거한 것"의 main 직접 push 차단 항목은 이 줄이 대체합니다. 근거: [2026-10-01 팀 현황과 결정](../decisions/2026-10-01-team-status-and-decisions.md).

## 유지하는 것

- CI `quality`: lint, 타입 검사, 모듈 경계, 계약 스키마, 테스트.
- CI `attribution`: AI/봇 이메일과 AI 공동 작성자·생성 표시 검사. 코드가 실제로 AI로 작성됐는지를 판별하는 검사는 아닙니다.
- CI `secrets`: push/PR 커밋 범위의 비밀키 검사.
- 로컬 훅: 설치한 경우 Python 코드 검사와 AI 트레일러 제거·AI 작성자 검사.
- 시크릿 커밋 금지, 기존 작업 보존. force push·이력 재작성·클라우드 삭제는 별도 사용자 지시 없이 하지 않습니다.

## 제거한 것

- 팀원 이메일 수집과 허용목록 검사.
- 커밋/PR 제목 형식, scope와 브랜치 이름 강제.
- main 직접 push 차단과 첫 push 전용 예외.
- 필수 PR·승인 1명·CODEOWNERS 승인·특정 merge 방식 강제.
- CI에서 이전 버전의 검사기를 복원하는 절차. 현재 커밋의 검사기를 사용합니다.

공유 코드나 계약을 바꾸면 영향을 받는 담당자와 조율하되, 별도 라벨·승인 대기로 개발을 막지 않습니다. Git 작성자 이름과 이메일은 Git 자체에 필요하며, 팀에 등록하는 절차는 없습니다.

## CI가 실행되는 조건

하네스는 `harness/`, 워크플로는 저장소 루트 `.github/workflows/`에 둡니다. main push 및 PR의 opened/synchronize/reopened/edited 이벤트에서 검사합니다. 일반 브랜치 push만으로는 실행하지 않습니다. GitHub Actions가 저장소에서 활성화되어 있어야 합니다.

CI에는 AWS 자격증명을 넣지 않습니다. 현재 CI는 개발 코드 검사용이며, 제품의 배포 파이프라인과 별개입니다. 실제 Actions 성공은 업로드 후 Actions 화면에서 확인합니다.

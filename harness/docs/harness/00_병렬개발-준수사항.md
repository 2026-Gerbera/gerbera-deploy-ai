# 00. 병렬 개발 준수사항과 인지사항

> 최신 협업 절차는 [Git·CI 최소 기준](03_깃-규칙과-AI-컨트리뷰터-차단.md)을 따른다. 과거 강제 승인·scope·브랜치 규칙은 적용하지 않는다.
> 기준: 앱 1개 구조(✅ 9/30 최신 개발자 문서 기준)
>
> 역할 코드: O1 정준우 · O2 김준석 · O3 장민영 · C2 안승환 · C3 양서윤 · C1 = 유상준 하차(10/1), C1은 정준우·김준석 분담(분담 ✅, 세부 🟡 김준석 확인) · TL = 하네스·계약 승인자(미지정, 결정 필요).

5명(10/1 유상준 하차)이 3일 동안 같은 저장소에서 병렬로 개발할 때 **반드시 지킬 것(준수 18)**과 **알고 있어야 할 위험·제약(인지 21)**입니다. 항목마다 확인 방법과 담당을 적었습니다. 담당은 [05 역할과 일정](../../../single-app/docs/05_역할과-일정.md)을 따릅니다: C1 정준우·김준석 분담(유상준 하차, 세부 🟡), C2 안승환, C3 양서윤, O1 정준우, O2 김준석, O3 장민영. "하네스 소유자"는 하네스·계약 승인자(@TL, 지정 대기 [I-30])입니다.

## 1. 준수사항 (반드시)

| # | 항목 | 내용 | 확인 방법 | 담당 |

| 2 | 계약 먼저 | 계약 v1(툴 카탈로그·입출력, plan.json·step 카탈로그, deploy.yaml, 어댑터 규약, 이벤트·스모크 결과, 실행 컨텍스트, ErrorCode)을 동결한 뒤 병렬 구현합니다. | [계약 인덱스](../contracts/README.md)의 상태 열이 "동결" | O2 + O1 + 하네스 소유자 |

| 6 | 로컬 검증 대기 지점 | 클라우드 트랙의 상태 변경 step(DB 마이그레이션, 서비스 전환)은 `wait_for: local_verified` 뒤에만 둡니다. 로컬이 실패하면 클라우드는 대기 지점에서 멈춥니다. 건너뛰기 플래그를 만들지 않습니다. | validate_plan(V8)·실행기 `check_signals`(W1) 테스트 | O2 / O1 |
| 7 | AI 경계 | [02](02_툴-작성-규약.md) C-6의 네 겹(import-linter 7개, ruff banned-api, call_ai 런타임 가드, LLM은 제안(JSON·HCL 초안)만 + 계획 검증·인프라 게이트)을 유지합니다. CI boundary가 실패하면 머지하지 않습니다. | `make boundary`, CI quality | 전원 |
| 8 | 비밀값과 AI | AI 입력은 redact를 통과해야 합니다. SECRET_KEY는 **시스템 난수**로 만들고(✅ 장부 13) 온프렘 `.env`/컨테이너, 클라우드 Secrets Manager로 갑니다. 사람이 관리 페이지에 입력하는 것은 도메인과 배포 승인뿐입니다. 파일, 로그, 이벤트, plan.json에 비밀값을 남기지 않습니다(참조만). | `tests/contract/test_ai_guard.py`, 리뷰 | O2 / C2 / O1 |
| 9 | 로그 마스킹 | run 로그, SSE 이벤트, collect_diagnostics 출력, 에러 메시지, AI 입력, CLI stderr에 `ddak.core.redact`를 공통 적용합니다. 길이는 4096자로 제한합니다. | `tests/unit/test_redact.py`, 실행기 테스트 | 하네스 소유자(redact) / 각 툴 |
| 10 | 시크릿 관리 | 저장소에는 키 이름만 둡니다(`env.example`). 로컬은 `.env`·`.secrets/`(커밋 금지), 클라우드는 Secrets Manager입니다. LLM·Jev 키는 공유 금고에 둡니다. Notion이나 채팅에 붙여넣지 않습니다. gitleaks는 로컬 훅(설치 시)과 CI에서 돌립니다. | CI secrets, `make secrets-scan` | 전원 |
| 11 | AWS 계정 | 서울(ap-northeast-2)만 씁니다. 개인별 자격증명을 씁니다(Identity Center 또는 IAM 사용자 + MFA). 키 공유를 금지합니다. 코드와 deploy.yaml에는 프로필 이름(`AWS_PROFILE`)만 둡니다. CI에는 AWS 자격증명을 넣지 않습니다. 테스트는 로컬 우선, 개발 중 클라우드 사용 최소화(✅ 장부 19). | `env.example`, ci.yml | 정준우(C1) [I-14] |
| 12 | AI Terraform만 | 콘솔 수동 변경을 금지합니다(재현성). AWS 리소스는 AI가 짠 Terraform을 사람이 승인한 뒤 `apply_infra`가 만듭니다(✅ 장부 21·23). 사람이 리소스 HCL을 쓰지 않습니다. 상태는 S3 백엔드(Terraform 1.11+, `use_lockfile`)를 씁니다. 로컬 tfstate·plan 파일은 커밋하지도 읽지도 않습니다(RDS 비밀번호 등 민감값이 평문으로 들어갈 수 있음). | `.gitignore`, `.claude/settings.json` deny, `infra/terraform/README.md` | 정준우(C1)·김준석 |
| 13 | 태그·비용 | 모든 리소스에 provider `default_tags`로 `Project=ddak`, `Owner=<역할>`, `Env=hackathon`, `ManagedBy=terraform`. AWS Budgets 알림을 ₩300,000의 50%·80%에 겁니다. 상시 과금 리소스 목록과 10/4 이후 cleanup 일정을 정합니다. LLM 호출은 run당 예산 상한을 둡니다. | `infra/terraform/README.md` | 정준우(C1) / O2 |
| 14 | 공급망 | Action은 40자리 SHA로 고정하고 버전을 주석으로 답니다. 저장소 설정 "Require actions to be pinned to a full-length commit SHA"를 켭니다. `uv sync --locked`. CI에서 원격 스크립트를 셸로 바로 실행하지 않습니다. 데모 Docker 베이스 이미지는 💭 digest로 고정합니다(Trivy Action 태그 탈취 CVE-2026-33634 같은 사례). | `tests/contract/test_ci_guard.py` | 하네스 소유자 / 정준우(C1) |
| 15 | 라이선스 | 외부 코드를 상당 부분 복사하면 원 저작권 고지와 허가 문구를 파일 머리와 `THIRD_PARTY_NOTICES.md`에 남깁니다(flaskr BSD-3). 해커톤 이전 작업물 재사용 규정은 확인되지 않았습니다. | 리뷰 | 전원 |
| 16 | 패치 커밋 격리 | AI 패치(토글 ON, 기본 OFF)가 만드는 커밋은 `var/demo-workspace`(별도 저장소, gitignore) 안에서만 만듭니다. **팀 저장소에 push하지 않습니다.** 그렇지 않으면 도구 신원이 컨트리뷰터가 됩니다. | CI attribution | O3 |
| 17 | 검증 증거 | PR에 head SHA, `make check` 요약, 해당하면 스모크·contract-smoke 수치를 적습니다. AI가 쓴 "통과했습니다" 문장은 증거가 아닙니다. | PR 템플릿 | 전원 |
| 18 | CI 약화 금지 | 실패 무시 설정(`continue-on-error`, 실패를 참으로 바꾸는 셸 구문), pytest 범위 축소 플래그(`-k`, `-m`, `--ignore`, `--deselect`)를 CI에 넣지 않습니다. 쓰기 권한, SHA로 고정하지 않은 `uses:`, `run:` 안의 `${{ }}`도 금지입니다. 새 `pytest.skip`에는 사유를 적습니다. | `tests/contract/test_ci_guard.py` | 하네스 소유자 |

## 2. 인지사항 (알고 있어야 할 위험·제약)

| # | 내용 | 대응 |
|---|---|---|
| 1 | AI 코딩 도구는 LangChain `@tool`이나 MCP SDK 코드를 만들기 쉽습니다. 이 저장소는 둘 다 쓰지 않습니다. | `src/ddak/core/tools/ping/` 템플릿 복사, ruff banned-api(`langchain`), 등록 규칙 검사(기동 실패) |
| 2 | 한 프로세스라 모든 모듈이 같은 env·파일·자격증명에 접근할 수 있습니다. "AI가 AWS에 닿을 수 없다"의 근거는 프로세스 격리가 아니라 **LLM이 툴을 호출하지 않고 제안(JSON·HCL 초안)만 돌려준다**는 구조와 계획 검증·인프라 게이트·사람 승인입니다. | 발표에서 "import 계약 + 런타임 가드로 강제, 물리 분리는 💭 컨테이너 모드"라고 정직하게 말함 |
| 3 | import-linter는 정적 import만 봅니다. | call_ai 런타임 가드(contextvar) |
| 4 | 로컬 훅은 모두 `--no-verify`로 우회됩니다. | CI 필수 체크(attribution)가 최종 관문 |
| 5 | 저장소 사이드바 Contributors는 Co-authored-by 트레일러를, REST contributors API는 author를 셉니다. 이력을 재작성해도 사이드바 캐시가 남을 수 있습니다. | 두 경로 모두 차단, 예방 |
| 6 | 비공개 저장소는 GitHub Free에서 보호 규칙과 필수 체크를 쓸 수 없습니다. | [I-6] 처음부터 공개 고려 |
| 7 | squash merge는 PR 안의 다른 작성자를 공동 작성자로 자동 추가한다는 보고가 있습니다(제3자 보고, GitHub 문서로 미확인). | AI 작성자·공동 작성자 표시 검사 |
| 8 | Claude Code의 `attribution` 같은 단일 값은 `.claude/settings.local.json`이 덮을 수 있습니다(permissions 목록은 병합되어 deny를 지울 수 없음). | 훅과 CI |
| 9 | Claude Code 하네스(이 하네스를 만든 세션 포함)는 기본으로 attribution 문구를 넣으라고 지시합니다. | 전원 개인 설정 필수 |
| 10 | moto로는 CodeBuild 단계, Docker Hub push·pull(AWS 밖), `repositoryCredentials` pull, ECS 안정화 대기를 검증할 수 없습니다(ECR 옵션의 인증·push도 마찬가지). RDS는 API만 흉내 냅니다. | Fake(단위) → moto(호출 형태) → 실제(수동 smoke) 세 층 |
| 11 | CodeBuild 프로비저닝, Fargate 기동, 일회성 마이그레이션 태스크 소요는 아직 재지 않았습니다. 3분 라이브 완주는 상한 추정이면 넘습니다. | 정준우(C1)·C2 실측(p50/p95만 말함) |
| 12 | CodeBuild 이미지를 Apple Silicon 온프렘에서 받을 때 CPU 아키텍처가 맞아야 합니다. 멀티아치의 index digest와 실제 플랫폼 digest를 구분합니다. | [I-21] 공통 index + 플랫폼별 실제 digest 검증 |

| 19 | 현장에서 외부 LLM API를 호출할 수 있는지, 네트워크가 안정적인지 모릅니다. | replay backend와 라벨. 운영진에게 질문 [I-22] |
| 20 | AI 출력의 비결정성 때문에 3분 데모가 매번 같을 수 없습니다. 안전장치 오탐(시크릿·IAM 문맥)으로 CLI가 `is_error`를 돌려줄 수 있습니다. | 규칙 대체 경로(재지시 1회 → 규칙 계획), "규칙 대체" 배지 |
| 21 | 레지스트리를 나중에 MCP로 노출해 대화형 AI에 연결하면 destructive 툴이 노출됩니다. | MCP 어댑터(P2)를 붙일 경우 읽기 전용 툴만 여는 모드 |

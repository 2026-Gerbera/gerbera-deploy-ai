## 4. 툴 추가 방법 (예: `prepare_db`)

`prepare_db`는 카탈로그상 `cd` 모듈(💭 트리), ④ 배포, 조건부 층, 대상 local·cloud, 담당 정준우(공통·onprem provider) / 안승환(aws provider)입니다([04 툴 카탈로그](04_툴-카탈로그.md)). cd 툴은 환경별 구현을 provider에 둡니다(✅ 장부 29). 다른 모듈(`plan`·`infra`·`ci`·`verify`·`ops`)의 툴은 기존처럼 `local.py`·`cloud.py`·`fake.py` 어댑터를 둡니다.

| 순서 | 할 일 | 파일 |
|---|---|---|
| 1 | 입출력 모델을 계약 변경 PR로 추가(필드는 계약 문서 기준) | `src/ddak/core/contracts/tools/prepare_db.py` |
| 2 | 템플릿 복사 후 어댑터 파일(`local.py`·`cloud.py`·`fake.py`)은 지움 | `cp -R src/ddak/core/tools/ping src/ddak/cd/tools/prepare_db` |
| 3 | `__init__.py`는 비워 둔다(와일드카드 import 계약 때문) | `…/prepare_db/__init__.py` |
| 4 | `tool.py`에 `@tool("prepare_db")` 등록, `select_provider(target, 모드)` → `provider.migrate_db(...)` | `…/prepare_db/tool.py` |
| 5 | provider 구현: `OnPremProvider.migrate_db`(was 호스트 일회성 컨테이너로 러너, 정준우), `AwsProvider.migrate_db`(ECS RunTask, 안승환), `FakeProvider`(정상/실패) | `src/ddak/cd/providers/{onprem,aws,fake}.py` |
| 6 | `FakeProvider`로 정상 1개·실패 1개 테스트 | `tests/unit/test_prepare_db.py` |

```python
# src/ddak/cd/tools/prepare_db/tool.py (모양만. 필드는 계약 문서가 정함)
from ddak.cd.providers import select_provider
from ddak.core.contracts.context import RunContext  # 모듈 최상단에서 import
from ddak.core.contracts.tools.prepare_db import PrepareDbInput, PrepareDbOutput
from ddak.core.registry import tool


@tool("prepare_db")  # 이름·위치(cd)·시그니처가 카탈로그와 다르면 앱 기동 실패
def prepare_db(inp: PrepareDbInput, ctx: RunContext) -> PrepareDbOutput:
    provider = select_provider(inp.target, ctx.adapter_mode)  # aws / onprem / fake, AI가 고르지 않음
    result = provider.migrate_db(inp.migrations, ctx)  # digest·DB 엔드포인트는 ctx(환경 정보)에서
    return PrepareDbOutput.from_result(inp, result)
```

| 언제 | 명령·화면 | 기대 |
|---|---|---|
| 첫날(전원) | 임시 저장소 테스트 커밋 후 `git log -1 --format='%an <%ae> \| %cn <%ce>%n%B'` | AI 트레일러·AI 신원·세션 링크 없음 |
| push 전 | `make attribution` | 통과 |
| 제출 전 | 저장소 사이드바 Contributors, `gh api repos/{owner}/{repo}/contributors --jq '.[].login'`, `git log --format='%an <%ae>\|%cn <%ce>' \| sort -u`, `make attribution FULL=1`, `make secrets-scan` | 팀원 6명만, 통과 |

- 오탐 주의: PR 본문에 "…generated with …(도구 이름)" 같은 영어 문장을 쓰면 우리 제품 설명이어도 거부됩니다. 한국어로 풀어 씁니다.
- git 메타데이터에서 AI를 빼는 것은 컨트리뷰터 목록 문제이지 AI 사용 사실을 숨기는 것이 아닙니다. AI 활용은 `docs/ai-usage/<역할>.md`, PR "AI 사용" 칸, README로 공개합니다.

## 12. AI Terraform 도구 설치와 공급망 (💭)

- 결정(✅ 장부 21): Terraform도 AI가 짭니다. 아래 도구·버전·명령은 고려안이고 담당은 유상준(C1)입니다(hadolint는 장민영). 확인 날짜 9/30(GitHub releases, PyPI).
- 이미지 저장소가 Docker Hub(✅ 장부 28)라 개발 PC에서 이미지를 받을 때도 Docker Hub pull 한도에 셉니다. 개발 중에는 개인 Docker Hub 로그인으로 받고, 팀 토큰(push·읽기 전용)은 CodeBuild·ECS·온프렘 호스트에만 둡니다.

**provider 미러 CLI 설정 예 (💭, P1)**

```hcl
# ~/.config/ddak/terraform.rc  →  export TF_CLI_CONFIG_FILE=~/.config/ddak/terraform.rc
provider_installation {
  filesystem_mirror {
    path    = "/Users/<me>/.cache/ddak/tf-mirror"
    include = ["registry.terraform.io/hashicorp/aws"]
  }
}
```

- `provider_installation`에 `filesystem_mirror`만 있으면 미러 밖 provider는 설치되지 않습니다. AI 파일에는 `provider`·`terraform` 블록이 없으므로(정적 게이트) 어떤 provider를 쓸지는 코드 소유 틀이 정합니다.

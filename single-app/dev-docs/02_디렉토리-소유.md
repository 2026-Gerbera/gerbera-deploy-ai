# 02. 디렉토리와 담당 (충돌 방지용, 9/30 밤 · 커밋 `7612150` 기준 · 10/1 providers 구조 반영 · 10/1 오후 C1 분담 반영)

> **📌 10/1 밤 회의:** 브랜치 이름 `prod`(개발자) → `ai-prod`(후보) → `main`(배포된 코드), 환경별 기록은 태그 `deployed/onprem`·`deployed/cloud`. 온프렘·클라우드 대기 지점 제거(독립 진행, 교차 검증은 둘 다 성공 시).

> **📌 10/1 저녁 변경 (트리거 개편):** `plan/intake`·`plan/detect`는 git 가져오기와 환경별 마지막 성공 `source_sha`(`prod` 커밋) 비교로, `plan/patch`는 패치 내용·비밀값 검사까지(ai-prod 커밋·push는 실행기, 정준우), `cloud/build`는 후보 커밋 빌드로 바뀝니다. 브랜치 감시·ai-prod 갱신·태그(`deployed/<환경>`)·`main` 기록 갱신 코드의 디렉토리는 아직 정하지 않았습니다(💭 `executor` 쪽, 정준우 결정). 상세: [docs/20](../../docs/20_트리거-개편-git-브랜치-기준.md)

> 원칙: **내 디렉토리만 고친다.** 다른 디렉토리는 안쪽 파일을 직접 import하지 말고 `__init__.py`의 공개 함수만 쓴다. ★ 공용은 채팅방에 먼저 알리고 작게 PR, 정준우가 확인한다. AI 호출은 `core/ai`(call_ai)로만, 허용된 디렉토리에서만.

- `cloud/deploy/providers/aws.py`는 위임만 한다. 각자 자기 메서드의 위임 한 줄만 고치고, 구현은 자기 모듈(`ecs.py`·`secrets.py`·`database.py` / `cloud/tls` / `cloud/health`)에 둔다. 새 코드는 `ddak.cloud.deploy.providers.aws`를 import한다.
- AI를 import할 수 있는 곳: `plan/analyze`, `plan/planner`, `plan/patch`, `plan/dockerfile`, `verify/diagnose`, `verify/report`, `cloud/infra`, `core/ai`. 나머지(`executor`, `cd`, `cloud/deploy·tls·health·build`, `onprem/*`, `ops`)는 금지이며 CI(import 규칙)가 막는다.
- C1 분담(유상준 10/1 하차, 분담 ✅ / 세부 🟡 김준석 확인): `generate_infra`는 김준석, 나머지 `cloud/infra`·`infra/terraform/`·`cloud/tls`는 정준우. 둘 사이 계약(🟡 먼저 합의): `generate_infra` 출력은 `var/infra/<run_id>/` 아래 HCL 파일 + 메타(리소스 목록·이유), backend·provider·자격증명 블록은 AI가 쓰지 않고 코드가 주입, 모든 `aws_iam_role`에 권한 경계 변수 필수, 입력은 분석 결과(비밀값 키 분류)와 환경 정보(`terraform output`).
- 각 디렉토리의 `__init__.py`에 계약 모양의 빈 구현(호출 시 "미구현")이 있다. 그 함수를 채우는 것부터 시작한다.

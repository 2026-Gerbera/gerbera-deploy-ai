## 1. 한 줄 요약과 이 역할의 핵심

**한 줄 요약:** 파이프라인이 배포할 앱(flaskr v1·v2)을 만들고, 두 환경이 똑같이 동작하는지 증명하는 검증(헬스·스모크·교차 비교)을 만듭니다.

| 왜 중요한가 | 설명 |
|---|---|
| 모두가 v1을 기다림 | 빌드(안승환), 배포(정준우·안승환), 분석(김준석), 인프라 요구(김준석 `generate_infra`), 화면(양서윤)이 전부 v1 이미지·`deploy.yaml`·env 키를 입력으로 씁니다. 10/1 정오에 v1이 안 뜨면 "전원 대기 위험"입니다(05 4-3 #1) |
| 내 스모크가 온프렘 합격 기준 | 온프렘 스모크 통과 = 신호 `local_verified`. 클라우드는 이 신호를 기다리지 않지만(✅ 10/1 밤 분리), 교차 비교는 이 신호와 `cloud_verified`가 둘 다 있어야 돕니다 |
| 차별점 | 교차 검증은 주제 문장에 들어 있습니다(✅ 장부 1). 발표 중심을 "환경 차이 흡수 + 교차 검증"으로 두는 문구는 💭입니다(06 13절 #21, 장부 30). 교차 비교 표가 그 증거입니다 |
| 시크릿 장면의 전제 | v1에 로그인·세션·`SECRET_KEY`가 **없어야** v2의 "새 비밀 → 시크릿·권한 추가 → 난수 주입" 장면이 성립합니다(💭 로그인 후보일 때의 전제, 이전 장부 32) |

### 5-2. 마이그레이션·DB

- [ ] **추가형만.** 허용: `CREATE TABLE`, NULL 허용 또는 상수 기본값 `ADD COLUMN`, 인덱스, 새 컬럼의 FK. 파괴형(`DROP`·`RENAME`·`MODIFY` 등)은 계획 검증 V10이 BLOCK합니다.
- [ ] **`init-db` 명령 삭제.** 원본 `schema.sql`은 `DROP TABLE`로 시작합니다. 파이프라인은 절대 부르지 않습니다.
- [ ] `up`: `GET_LOCK('flaskr_migrate', 10)` → checksum 드리프트 재확인 → 문장 분리 → **문장 단위 가드**(`information_schema`로 이미 있으면 건너뜀) → 파일 끝에 `schema_migrations` 기록 → `RELEASE_LOCK`.
- [ ] MySQL DDL은 암묵 커밋입니다. 중간 실패 시 앞 문장이 남으므로 재실행이 안전해야 합니다.
- [ ] `precheck`: 연결(클라우드는 CA 검증 TLS), `VERSION()`·`sql_mode`·collation·time_zone·`require_secure_transport`·`Ssl_version`, 대기 파일 lint, checksum 드리프트. `mode=bootstrap`이면 DB가 비었는지(V18).
- [ ] `verify`: 기대 버전 = 최대 버전, 스키마 서명(정렬한 `information_schema` sha256), DB 지문.
- [ ] **DB는 롤백하지 않습니다(✅ 장부 6).** 그래서 **v1 코드 × 0002 스키마**가 동작해야 합니다(`author_id` NULL 허용). SQL로는 9/30 확인했고 앱 수준은 확인 필요입니다.
- [ ] 클라우드 앱 계정은 DML만 + `REQUIRE SSL`(✅ 장부 23). 💭 마이그레이션은 별도 DDL 계정(`DATABASE_URL_MIGRATOR`, 장부 35). 러너는 받은 `DATABASE_URL`만 씁니다.

### 5-3. 헬스·버전

- [ ] `/health/live`: DB를 보지 않음(💭 ALB 헬스 경로 후보, D21).
- [ ] `/health/ready`: `SELECT 1` + `schema_migrations` 최대 버전 ≥ **이미지 안 `migrations/`에서 계산한 기대 버전** + TLS 여부. 뒤처지면 **503**.
  - 이것이 E2E 실패 주입(온프렘 마이그레이션 건너뛰기 → v2 ready 503 → 온프렘만 롤백, 클라우드는 독립적으로 계속 진행)의 근거입니다.

- [ ] `/version`에 DB 버전·sql_mode 같은 지문을 넣지 않습니다(러너 `verify`로만).

| flaskr(#1) | `schema.sql`이 `DROP TABLE`로 시작, `init-db`가 데이터 삭제 | 명령 삭제 |
| flaskr(#2) | `SECRET_KEY="dev"` 기본값이면 주입이 빠져도 앱이 뜸(세션 위조) | v2는 `require_env`(위치는 확인 필요) |
| flaskr(#3) | 원본 v1도 `flash()` 때문에 세션 필요 | v1에서 flash·세션 제거 |
| flaskr(#4) | 테이블 `user`는 MySQL 키워드 | `users` |
| flaskr(#5) | INNER JOIN이면 v1 익명 글이 사라짐(두 환경 똑같이 → 비교로 못 잡음) | LEFT JOIN, 스모크 S9 |
| flaskr(#6) | 원본 Edit 링크 복사 시 목록 500 | 넣지 않음, 스모크 S7 |
| flaskr(#7) | `users.created`가 있으면 목록 쿼리 1052(모호) | users에 created 없음 + `p.created` |
| flaskr(#8) | `AUTOINCREMENT`는 1064, `TEXT UNIQUE`는 1170 | 03 4-1 DDL |
| flaskr(#9) | 같은 초 INSERT면 순서 뒤섞임 | `ORDER BY created DESC, id DESC` |
| MySQL(#11) | PyMySQL에 `ssl_ca=` 키워드만 주면 인증서 검증 안 함 | URL `?ssl_ca=`(SQLAlchemy가 `ssl={"ca":…}`로 넘김) 또는 `ssl={"ca":…}` |
| MySQL(#12) | PyMySQL ≥1.2.0은 옵션이 없으면 검증 없는 TLS 시도 | 온프렘 전송 방식 결정(N8) |
| MySQL(#13) | `cryptography` 없으면 8.4 기본 인증 실패, PyMySQL 1.2.1 미만은 SQL 인젝션 | `PyMySQL>=1.2.1` + `cryptography` |
| MySQL(#14) | RDS 인증서 CN = 엔드포인트 | IP·별칭 CNAME으로 접속 금지 |
| MySQL(#16) | DDL 암묵 커밋, `ADD COLUMN IF NOT EXISTS`·`CREATE INDEX IF NOT EXISTS` 미지원(1064), 재실행 1060·1826 | 문장 단위 가드 |
| MySQL(#17, R6) | RDS 기본 sql_mode가 비엄격일 수 있음 → 긴 아이디가 잘린 채 가입 | 앱 길이 검증(1~50자), S13(P1). 10/3: 글 제목 200자 검증 + 스모크 B2.long, sql_mode는 S12가 비교(입력 경로 생기면) |
| MySQL(#18) | `utf8mb4_0900_ai_ci`는 대소문자 무시. 개발 SQLite와 다름 | 스모크 아이디 소문자 |
| MySQL(#19·#21) | TIMESTAMP는 세션 time_zone 영향, 문자셋 미지정 시 한글 `?` | 연결마다 `+00:00`, `charset=utf8mb4` |
| SQLAlchemy(#22) | 풀링 + REPEATABLE-READ에서 트랜잭션을 안 닫으면 오래된 값 | 요청 단위 `engine.begin()` |
| SQLAlchemy(#23) | gunicorn `--preload`로 fork 전에 엔진 생성 시 소켓 공유 | fork 뒤 생성 또는 `engine.dispose()` |
| nginx(#25) | `X-Forwarded-Proto $scheme`으로 덮어쓰면 WAS가 http로 인식 | `map`으로 ALB 값 전달(v1부터) |
| nginx(#27) | upstream 이름을 시작 때 한 번만 해석 → WAS 재생성 시 502 | was 고정 IP 또는 `resolver`. **10/1 E2E에서 먼저 깨질 곳** |
| nginx(#28) | v2에서 nginx를 안 바꿈 | `/health/*`·`/version` 프록시가 v1에 있어야 함 |
| 쿠키(#26, E5) | Safari·파이썬 `http.cookiejar`는 `http://`에서 Secure 쿠키를 안 보냄 | 온프렘 Secure·ProxyFix는 `public_url` 스킴을 따름(https면 켬, http면 끔), ProxyFix hop 💭(cloudflared → nginx → Traefik, 헤더 확인 후 확정), 데모 브라우저 Chrome |
| ProxyFix(#24) | `x_proto=2`면 스킴이 http로 남음 | 클라우드 `x_for=2, x_proto=1`. "ProxyFix로 로그인을 고쳤다"고 말하지 않음 |
| 빌드(#32) | 멀티아치 인덱스 digest ≠ 플랫폼별 digest | 멀티 아키텍처 기본(✅ 9/30). "같은 이미지"는 index digest, 각 환경의 실제 digest는 index의 플랫폼 항목 소속으로 확인 |
| 저장소(#34) | `certs/global-bundle.pem`이 코드 템플릿의 `*.pem` 무시 규칙에 걸림 | N24 결정(예외 명시 또는 CodeBuild에서 받기) |
| 저장소(#35) | 개발 환경 파일을 `.env.development`로 두면 `.env.*` 무시 규칙에 걸려 커밋 안 됨 | 💭 `dev.env`처럼 `.env.`로 시작하지 않는 이름 |
| 개발 PC(2-5) | MySQL DDL은 SQLite에서 안 돎 → 마이그레이션 파일을 개발 PC와 공유 불가 | N7 결정(`create_all()` 개발 명령 / 개발도 MySQL) |
| AI Dockerfile(#55) | 검증 빌드에서 AI가 쓴 `RUN`이 실행됨, 컨텍스트에 비밀 파일 유입 가능 | 정적 검사 먼저, 코드 소유 `.dockerignore`, push·비밀 없는 빌드 |
| 시크릿 장면(E1-b, #52) | IAM 전파 전이면 새 태스크가 새 시크릿을 못 읽음(`ResourceInitializationError`) | 내 몫은 원인 설명 규칙 시그니처에 넣는 것 |

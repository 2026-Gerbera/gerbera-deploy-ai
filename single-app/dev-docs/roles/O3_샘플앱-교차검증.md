## 1. 한 줄 요약과 이 역할의 핵심

**한 줄 요약:** 파이프라인이 배포할 앱(flaskr v1·v2)을 만들고, 두 환경이 똑같이 동작하는지 증명하는 검증(헬스·스모크·교차 비교)을 만듭니다.

| 왜 중요한가 | 설명 |
|---|---|
| 모두가 v1을 기다림 | 빌드(안승환), 배포(정준우·안승환), 분석(김준석), 인프라 요구(유상준), 화면(양서윤)이 전부 v1 이미지·`deploy.yaml`·env 키를 입력으로 씁니다. 10/1 정오에 v1이 안 뜨면 "전원 대기 위험"입니다(05 4-3 #1) |
| 내 스모크가 관문 | 온프렘 스모크 통과 = 신호 `local_verified`(G1). 이 신호가 있어야 클라우드의 DB 마이그레이션·서비스 전환·인프라 apply가 시작됩니다(✅ 장부 6) |
| 차별점 | 교차 검증은 주제 문장에 들어 있습니다(✅ 장부 1). 발표 중심을 "환경 차이 흡수 + 교차 검증"으로 두는 문구는 💭입니다(06 13절 #21, 장부 30). 교차 비교 표가 그 증거입니다 |
| 시크릿 장면의 전제 | v1에 로그인·세션·`SECRET_KEY`가 **없어야** v2의 "새 비밀 → 시크릿·권한 추가 → 난수 주입" 장면이 성립합니다(✅ 장부 32) |

### 5-2. 마이그레이션·DB

- [ ] **추가형만.** 허용: `CREATE TABLE`, NULL 허용 또는 상수 기본값 `ADD COLUMN`, 인덱스, 새 컬럼의 FK. 파괴형(`DROP`·`RENAME`·`MODIFY` 등)은 계획 검증 V10이 BLOCK합니다.
- [ ] **`init-db` 명령 삭제.** 원본 `schema.sql`은 `DROP TABLE`로 시작합니다. 파이프라인은 절대 부르지 않습니다.
- [ ] `up`: `GET_LOCK('flaskr_migrate', 10)` → checksum 드리프트 재확인 → 문장 분리 → **문장 단위 가드**(`information_schema`로 이미 있으면 건너뜀) → 파일 끝에 `schema_migrations` 기록 → `RELEASE_LOCK`.
- [ ] MySQL DDL은 암묵 커밋입니다. 중간 실패 시 앞 문장이 남으므로 재실행이 안전해야 합니다.
- [ ] `precheck`: 연결(클라우드는 CA 검증 TLS), `VERSION()`·`sql_mode`·collation·time_zone·`require_secure_transport`·`Ssl_version`, 대기 파일 lint, checksum 드리프트. `mode=bootstrap`이면 DB가 비었는지(V18).
- [ ] `verify`: 기대 버전 = 최대 버전, 스키마 서명(정렬한 `information_schema` sha256), DB 지문.
- [ ] **DB는 롤백하지 않습니다(✅ 장부 6).** 그래서 **v1 코드 × 0002 스키마**가 동작해야 합니다(`author_id` NULL 허용). SQL로는 9/30 확인했고 앱 수준은 확인 필요입니다.
- [ ] 클라우드 앱 계정은 DML만 + `REQUIRE SSL`(✅ 장부 23). 💭 마이그레이션은 별도 DDL 계정(`DATABASE_URL_MIGRATOR`, 장부 35). 러너는 받은 `DATABASE_URL`만 씁니다.

### 5-3. 헬스·버전

- [ ] `/health/live`: DB를 보지 않음(💭 ALB 헬스 경로 후보, D21).
- [ ] `/health/ready`: `SELECT 1` + `schema_migrations` 최대 버전 ≥ **이미지 안 `migrations/`에서 계산한 기대 버전** + TLS 여부. 뒤처지면 **503**.
  - 이것이 E2E 실패 주입(온프렘 마이그레이션 건너뛰기 → v2 ready 503 → 온프렘만 롤백, 클라우드 `ABORTED_AT_GATE`)의 근거입니다.
- [ ] `/version`: release_id, source_sha, app_env, schema_expected, base_url, `db.dialect`, `db.host`(**가림**), `db.tls`, `db.tls_verified`.
- [ ] `/version`에 DB 버전·sql_mode 같은 지문을 넣지 않습니다(러너 `verify`로만).
- [ ] `/version`은 digest 근거가 아닙니다. digest는 `docker inspect`(온프렘)·`describe_tasks`(클라우드)로 보고, 실제 digest가 manifest index의 플랫폼 항목에 속하는지로 판정합니다(V20).

### 5-4. 스모크

- [ ] 같은 스크립트를 두 환경에서 `requests.Session`으로 **독립** 실행합니다(세션 쿠키는 환경 간 재사용 불가).
- [ ] 대상 주소는 입력이 아니라 실행 컨텍스트에서 받습니다(온프렘 인벤토리 `public_url`, 클라우드 `https://<cloud_domain>`).
- [ ] 온프렘은 내부 `http://`로 돕니다(로컬 HTTPS ⏸). 클라우드 HTTPS는 인증서 검증을 끄지 않습니다.
- [ ] 스모크 아이디는 `smoke-<run>` 소문자(MySQL 대소문자 무시 collation 때문).
- [ ] 결과에 세션 쿠키 **값**·비밀값을 넣지 않습니다. 쿠키는 이름·HttpOnly·SameSite·Path만.
- [ ] 스모크 데이터는 💭 남기고 `[smoke <run>]`로 표시(D19 미결).
- [ ] 통과해야 `local_verified`가 열립니다. 느슨하면 나쁜 코드가 클라우드로, 불안정하면 클라우드가 영영 안 갑니다.

## 7. AI 사용 경계

| AI가 하는 것 | AI가 하지 않는 것 |
|---|---|
| (P1) `diagnose_parity_gap`: 원인 범주·설명·다음 조치 **제안**. 가설로 표시 | 스모크·헬스·비교의 통과 판정 |
| 💭 (P1) `generate_dockerfile`: Dockerfile·`.dockerignore` **초안** | 롤백 결정, 관문(G1) 판단, 재배포 |
| (P0, 토글 ON만) `patch_*`: 패치 diff **제안** | 보고 심각도(고정 표가 정함) |
| (김준석 영역) 내 코드의 키를 secret/plain/address로 분류 | 예상된 차이 목록 정하기 |
| | 비밀값 보기·생성(`SECRET_KEY` 난수는 코드의 `secrets`가 만듦) |
| | Dockerfile 검사 통과 판정, 빌드·push, 승인 |
| | 패치 적용, 팀 저장소 push |

- AI 호출은 `call_ai` 하나로만 합니다(backend: 개발 `cli` / 데모 `api` / 테스트 `replay`, ✅ 장부 7). 테스트·CI는 `replay`입니다.
- `validate_dockerfile`은 `generate_dockerfile`·AI 관문을 import하지 않습니다(검사기와 생성기 분리).
- 로그·diff·코드는 신뢰할 수 없는 입력입니다. `call_ai`가 감싸고 redact합니다. AI 출력은 관리 페이지에서 이스케이프한 텍스트로만 보입니다.
- 토글 OFF(일반 실행 기본, 데모는 ON ✅ 9/30 오후)는 UI가 아니라 계획 검증(V9)이 서버에서 강제합니다. 코드가 원인인 문제는 보고로 알립니다.

| flaskr(#5) | INNER JOIN이면 v1 익명 글이 사라짐(두 환경 똑같이 → 비교로 못 잡음) | LEFT JOIN, 스모크 S9 |

| flaskr(#8) | `AUTOINCREMENT`는 1064, `TEXT UNIQUE`는 1170 | 03 4-1 DDL |
| flaskr(#9) | 같은 초 INSERT면 순서 뒤섞임 | `ORDER BY created DESC, id DESC` |

| MySQL(#13) | `cryptography` 없으면 8.4 기본 인증 실패, PyMySQL 1.2.1 미만은 SQL 인젝션 | `PyMySQL>=1.2.1` + `cryptography` |
| MySQL(#14) | RDS 인증서 CN = 엔드포인트 | IP·별칭 CNAME으로 접속 금지 |
| MySQL(#16) | DDL 암묵 커밋, `ADD COLUMN IF NOT EXISTS`·`CREATE INDEX IF NOT EXISTS` 미지원(1064), 재실행 1060·1826 | 문장 단위 가드 |

| SQLAlchemy(#23) | gunicorn `--preload`로 fork 전에 엔진 생성 시 소켓 공유 | fork 뒤 생성 또는 `engine.dispose()` |

| ProxyFix(#24) | `x_proto=2`면 스킴이 http로 남음 | 클라우드 `x_for=2, x_proto=1`. "ProxyFix로 로그인을 고쳤다"고 말하지 않음 |
| 빌드(#32) | 멀티아치 인덱스 digest ≠ 플랫폼별 digest | 멀티 아키텍처 기본(✅ 9/30). "같은 이미지"는 index digest, 각 환경의 실제 digest는 index의 플랫폼 항목 소속으로 확인 |

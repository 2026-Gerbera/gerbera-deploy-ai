## 1. 한 줄 요약과 핵심

**한 줄 요약:** 클라우드에 뜬 앱이 정말 맞게 떴는지 코드로 확인하고(헬스·스모크·TLS·보고), 사람이 보고 승인하는 관리 페이지를 만듭니다.

| 왜 중요한가 | 설명 | 근거 |
|---|---|---|
| 사람 관문이 여기 있음 | AI 제안(Terraform·IAM·Dockerfile)은 검증과 사람 승인 뒤에만 코드가 실행합니다. IAM은 사람이 승인해야 생깁니다. 그 승인이 이 화면에서 일어납니다 | 장부 4-a ✅, 23 ✅, 4-b 💭 |
| 심사위원이 보는 화면 | 3분 데모의 대부분이 관리 페이지입니다. 흐름(시크릿 장면 승인 포함)을 한 화면에서 이해시켜야 합니다 | [05 1절](../../docs/05_역할과-일정.md) 성공 기준, [03 10절](../../docs/03_골든패스-시나리오.md#10-3분-데모-대본-초-단위) |
| 배포를 증명함 | "트래픽이 간다"는 증거가 아닙니다(ALB는 대상이 전부 unhealthy여도 보냄). 실제 digest·스모크·TLS로 확인합니다 | [01 5-7절](../../docs/01_아키텍처.md) |
| HTTPS의 시작점 | 도메인은 사람이 관리 페이지에만 입력합니다. 도메인이 없으면 ACM 인증서를 못 받습니다. 인증서 사전 발급 마감은 10/1입니다 | 장부 17 ✅, R3 |

**성공 기준(05, 💭):** `verify_tls` 합격 기준 7개 pass. 심사위원이 관리 페이지 한 화면에서 흐름(시크릿 장면 승인 포함)을 이해.

### 5-2. POST 보호 (💭 P0, 정준우와)

- 대상: [기반 승인]·[패치 diff 승인]·[IAM·인프라 승인]·[Dockerfile 승인]·[배포](한 번 클릭 승인 포함). 💭 권고: 설정 저장·"도메인 연결"도 같은 검사.
- `Host`가 `127.0.0.1:<포트>`가 아니면 거부(DNS rebinding).
- `Origin` 검사 + CSRF 토큰(CSRF).
- 이유: 운영자 브라우저의 악성 페이지가 승인 POST를 대신 보낼 수 있음. 부트스트랩이면 관리자 자격 apply가 걸림([IAM 조사 6절 E31](../../../research/2026-09-30_IAM-최소권한-설계.md)).
- 로그인 + `SameSite=Strict`은 외부 공개 때(⏸ R2).

### 5-3. 렌더링과 비밀값

- [ ] 모든 텍스트를 HTML 이스케이프: LLM 출력, `reason`, HCL, Dockerfile, 로그, 스모크 응답. 마크다운 이미지·링크 자동 로드 금지
- [ ] 비밀값은 표시하지 않음: SECRET_KEY는 `●●●● (64자, 생성 시각)`, 시크릿은 ARN(가림)만
- [ ] `DATABASE_URL`은 `mysql://flaskr_app:●●●@10.0.●.13:3306/flaskr` 모양
- [ ] 계정 ID, DB 지문(sql_mode·버전)은 표시하지 않음
- [ ] 💭 개발값(`dev`, `sqlite:`, `localhost`)은 그대로 보여 줌. 바뀌는 장면이 요점
- [ ] 진행 이벤트는 정준우가 redact해서 줌. 화면에서 다시 이스케이프
- [ ] 코드 수정 토글: 일반 실행 기본 OFF, 데모는 ON ✅(9/30 오후, 장부 16 대체). 화면에 상태를 보여 주되, 강제는 서버(계획 검증 V9)

### 5-4. 설정 화면

- 저장 필드(C-15): `cloud_domain`, `dns_mode`, `hosted_zone_id`, 토글 + `version`·`updated_by`·`updated_at`, 변경 이력. 💭 `wildcard` 옵션은 HTTPS 조사에만 있음.
- 형식 검증(HTTPS 조사 7절): 소문자 변환, 끝 점 제거, `https://`·포트·경로·IP·와일드카드 입력 거부, 253자·라벨 63자, 한글 도메인은 punycode, `amazonaws.com`·`cloudfront.net`·`elasticbeanstalk.com` 거부, route53이면 영역 이름 접미사 확인, external이면 "apex 불가, 서브도메인 입력" 안내.
- 도메인은 설정 → run 시작 때 스냅샷 → `ctx.cloud_domain`으로만 흐릅니다. 툴 파라미터·계획·`deploy.yaml`·AI 입력에는 넣지 않습니다(✅ 장부 17). 스냅샷은 정준우(실행기)가 만듭니다.
- 변경 경고: 인증서 재발급 필요(최대 30분 이상 Pending 가능), IAM 정책의 도메인 조건도 다시 적용해야 함(IAM 조사 11절 #27), 💭 마감 뒤 잠금.
- external이면 검증 CNAME 안내(Name·Value 복사, 서비스 CNAME → ALB DNS 이름).
- 인증서 상태: 없음 / 요청됨 / 검증 대기(경과 시간) / 발급됨(만료일·남은 일수) / 사용 중 / 실패(FailureReason).

### 5-5. 검증 툴

| 툴 | 꼭 지킬 것 |
|---|---|
| `health_check` | digest는 `/version`이 아니라 ECS `describe_tasks`의 `imageDigest`로 보고, manifest index의 플랫폼 항목 소속으로 판정(플랫폼 digest는 환경마다 다를 수 있음). "트래픽이 간다"를 통과 근거로 쓰지 않음(ALB fail-open). ECS `COMPLETED`를 기다리지 않음(새 대상 healthy + `/version` release_id 일치) |
| `smoke_test` | 환경마다 독립 `requests.Session`(세션 쿠키는 SECRET_KEY 서명이라 환경 간 재사용 불가). 클라우드 주소는 `https://<cloud_domain>`. S5 쿠키 비교에서 Secure·값 제외. 스모크 데이터는 `[smoke <run>]` 표시(D19 💭) |
| `verify_tls` | ALB DNS 이름에 SNI=`cloud_domain`으로 접속(DNS와 분리). V8은 `SECLEVEL=0`으로 붙어 서버 alert일 때만 pass, 그 밖은 inconclusive. V9 HSTS는 앱 200 응답으로 확인. 전체 합격 = V1~V7 |
| 공통 | 읽기만(쓰기 API 호출 없음). 어댑터가 `ctx.deadline`을 스스로 지킴(스레드 안 boto3는 취소로 안 멈춤). 초기 타임아웃 💭: health·smoke 60초, `verify_tls`·`post_report` 30초 |

**`verify_tls` 검사 9개** (HTTPS 조사 6절, 기준 💭)

| # | 검사 | 합격 기준 | 필수 |
|---|---|---|---|
| V1 | DNS 연결 | `getaddrinfo(cloud_domain)` ∩ `getaddrinfo(ALB DNS 이름)` 교집합 있음 | 예 |
| V2 | 핸드셰이크·체인·호스트명 | `ssl.create_default_context()` 검증 오류 없음 | 예 |
| V3 | 협상 버전 | TLS 1.2 이상(1.3 기대, 표시) | 예 |
| V4 | 인증서 내용 | 발급자 O=Amazon, 남은 일수 30일 이상 | 예 |
| V5 | ACM 교차 확인 | ISSUED, InUseBy에 ALB ARN, NotAfter가 V4와 같음 | 예 |
| V6 | 리스너 설정 | 443 SslPolicy = 허용 값(`ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09`), 80 = 301 → HTTPS:443 | 예 |
| V7 | http 리다이렉트 | `http://cloud_domain/` → 301, Location이 `https://cloud_domain/`으로 시작 | 예 |
| V8 | TLS 1.0/1.1 거부 | 서버 alert `TLSV1_ALERT_PROTOCOL_VERSION` | 표시만 |
| V9 | HSTS | 앱 200 응답에 `Strict-Transport-Security` | 표시만 |

- 이 V1~V9는 계획 검증 규칙 V1~V26과 다른 번호입니다.
- 필요 권한(읽기): `acm:DescribeCertificate`, `elasticloadbalancing:Describe*`, `route53:ListResourceRecordSets`. 실행기에서 공인 인터넷 80·443으로 나갈 수 있어야 합니다.

### 5-6. 보고와 실패 처리

- `post_report`는 `run: finally`입니다. 앞 step·트랙이 실패해도 마지막에 돕니다.
- 심각도는 고정 표(코드)가 정합니다. AI는 `summary`(≤400자)·`suggested_next`(≤200자) 설명만 씁니다.
- AI 요약이 실패하면 규칙 카드만 냅니다. 보고가 실패해도 run 결과는 그대로입니다.
- 내 검증이 실패하면 실행기가 **그 환경만** 롤백합니다(정준우, ✅ 장부 6). `verify_tls` 실패 때 롤백할지는 N10 미결(💭 롤백 없이 보고. TLS·DNS는 앱 롤백으로 안 고쳐짐).
- 실패 화면은 원인 설명(장민영)의 규칙 시그니처를 보여 줍니다: `ResourceInitializationError`(시크릿 읽기 권한·`repositoryCredentials`), `CannotPullContainerError`(Docker Hub 토큰·한도·퍼블릭 IP), MySQL 3159(평문 거부), `KeyError: 'SECRET_KEY'`.

## 7. AI 사용 경계

| 영역 | AI가 하는 것 | AI가 하지 않는 것 |
|---|---|---|
| 채팅 | 문장 → 의도 JSON(`action` enum, `target`, `ref`). 의도 함수는 김준석, 위치는 N3 | 실행·승인. `ref` 존재 판단(코드가 확인). 실행은 사람의 [배포] 클릭 |
| 보고 | 헤드라인 ≤80자 + 불릿 ≤5개 요약(P1, 선택) | 성공·실패 판정, 심각도. 실패하면 규칙 카드만 |
| 원인 설명 표시 | (장민영의 툴) 범주·설명, `is_hypothesis` 표시 | 롤백·관문 판단 |
| 승인 화면 | HCL 초안의 `assumptions`·패치 diff 텍스트(표시만) | plan 요약 작성(코드가 `terraform show -json`에서 만듦), 승인 |
| 검증 툴 | 없음 | `health_check`·`smoke_test`·`verify_tls`는 AI를 부르지 않음 |
| LLM 연결 카드 | 없음 | 웹에서 Claude 로그인·토큰 입력을 받지 않음(약관, 장부 7 ✅) |
| Slack | 의도 JSON만(P1) | 승인. Slack 쪽 LLM은 API 키 backend만 |

- 웹 모듈은 AI 관문(`core.ai`)을 직접 import하지 않습니다. 채팅 의도는 `uses_ai` 툴을 거칩니다([04 4-4절](../../docs/04_툴-카탈로그.md)). 웹은 레지스트리를 이름으로 조회만 합니다.
- LLM 출력은 이스케이프한 텍스트로만 렌더링합니다.
- 라벨: replay면 "저장된 응답", 캐시면 `source=cache`, 규칙 대체면 "규칙 대체" 배지. Jev 판정이면 확률·지연·비용(예: "Jev 0.4초 · $0.00004 · jev-1.13.0").

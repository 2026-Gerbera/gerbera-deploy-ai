|---|---|

## 3. 파이프라인에서 내 위치

### 3-1. 5단계에서

| 단계 | 내가 하는 것 | 다른 사람이 하는 것 |
|---|---|---|
| ① 플랜 | run 시작 때 **환경 정보 스냅샷**(`RunContext`) 조립. 입구 툴이 이 함수를 부름 💭 | 입구·분석·계획(김준석 O2), AI Terraform 초안(유상준 C1) |
| ② 계획 검증 | 검증 뒤 **사람 승인 받기**(`request_approval`) | `validate_plan`(김준석), `validate_infra`·`plan_infra`(유상준), 승인 화면(양서윤 C3) |
| ③ 빌드 | build 트랙 실행, digest로 manifest 초안, 신호 `images_ready` 열기. 온프렘 pre-pull(위치 미정) | CodeBuild → Docker Hub(`build_image` cloud·`push_image`, 안승환 C2) |
| ④ 배포 | 잠금. **로컬 트랙 전부**(onprem provider: `.env`, 마이그레이션, 컨테이너 교체). 클라우드 트랙 호출과 대기 지점. 실패 시 롤백 | 클라우드 구현(aws provider 안승환, `apply_infra`·`ensure_tls` 유상준) |
| ⑤ 검증 및 보고 | 헬스·스모크 호출, 신호 열기, G2 대기, `record_deploy_log`, 진행 이벤트 | `health_check`(local 장민영 O3 / cloud 양서윤), `smoke_test`, `compare_env_results`(장민영), `post_report`(양서윤) |

```
[승인] → 잠금 ─┬ build : build.was ─────────────────────────────▶ images_ready (G0)
               ├ local : (G0 대기) config → db → was → health → smoke ─▶ local_verified (G1)
               └ cloud : tls(확인) ···(G1 대기)··· infra → secrets → config → db → app → health·tls·smoke ─▶ cloud_verified
compare (local_verified ∧ cloud_verified = G2) → finally: report → record_deploy_log → 잠금 해제
```

- 신호는 4개로 고정입니다: `infra_ready`(💭 인프라 apply 뒤), `images_ready`, `local_verified`, `cloud_verified`. AI는 신호를 만들거나 지울 수 없습니다.
- 로컬 트랙은 클라우드를 기다리지 않습니다(W3). 온프렘에는 인프라 step과 TLS step이 없습니다(로컬 HTTPS ⏸).

| # | 과정 |
|---|---|
| B1 | 매 step 직전 `plan_hash` 대조(V12). 다르면 중단 |
| B2 | 툴 입력의 `run_id`·`target`·`tier`·`lock_token`은 실행기가 채우고 스키마를 다시 검증 |

| B5 | 타임아웃은 어댑터가 `ctx.deadline`을 스스로 지킴(docker SDK timeout, subprocess kill). 8절 #1 |
| B6 | 트랙이 끝날 때 자기가 못 연 신호는 실패로 닫음(교착 방지) |

**롤백 (✅ 장부 6)**

| # | 규칙 |
|---|---|
| R1 | 해당 환경만, 앱만, 그 환경 `previous_release`의 digest로. 온프렘은 바뀐 tier 컨테이너를 이전 digest로 재생성(수 초 중단 허용) |
| R2 | 롤백은 **현재 상태를 조회한 뒤** 필요한 것만(멱등). 타임아웃 뒤에는 실제 상태를 모름 |
| R3 | DB는 되돌리지 않음(추가형 마이그레이션만). 설정(`.env`)도 되돌리지 않음(추가형 키 전제, 확인 필요) |
| R4 | 인프라(Terraform)는 되돌리지 않음. v2 인프라 apply 실패면 서비스는 아직 v1이라 앱 롤백은 할 일이 없음 → run `FAILED_CLOUD`, 환경 `DIVERGED` |
| R5 | 롤백 실패 → `NEEDS_HUMAN`, 잠금 유지 |
| R6 | 부트스트랩은 롤백 대상이 없음 → 중지(온프렘은 `ddak.managed=true` 라벨 컨테이너만 제거) |

**finally**
- [ ] `verify.report`(`run: finally`) 실행. 실패해도 run 결과는 그대로.
- [ ] `record_deploy_log`: `env_release`·마지막 성공 digest·마지막 성공 스냅샷 해시 목록·인프라 요구 해시 갱신.
- [ ] 잠금 해제(`NEEDS_HUMAN`이면 유지).

**비밀값**
- [ ] SECRET_KEY = `secrets.token_hex(32)`(64자). 환경 간 공유 금지, 이미 있으면 재사용(매번 바꾸면 전원 로그아웃). 생성 주체는 N4(10절).
- [ ] `.env`는 0600. 기록에는 경로만. 비밀 필드는 `SecretStr`.
- [ ] manifest·이벤트·`context.json`·로그에는 참조(파일 경로·ARN)만. 모든 이벤트 문자열은 redact.
- [ ] `.env` 값은 `docker inspect`로 보임 → 한계로 명시(N4 헬퍼 안이 줄이는 방법).
- [ ] 개발값(`dev`, `sqlite:`, `localhost`)을 배포 값으로 쓰지 않음(V21은 김준석 검증, 쓰는 쪽은 나).

**docker 코드 정책 (진짜 방어선)**
- [ ] 이미지는 `docker.io/<조직>/<이미지>@sha256:<64hex>` digest로만 생성. 태그 참조 거부.
- [ ] privileged, cap_add, bind mount, host network·pid 거부(named volume만).
- [ ] 생성 때 `ddak.managed=true` 라벨. stop·rm은 이 라벨이 있는 컨테이너만.
- [ ] 앱 컨테이너에 docker.sock·호스트 FS 금지. docker CLI를 쓰면 리스트 인자(`shell=True` 금지).

**환경 정보**
- [ ] Terraform state 원문을 파싱하지 않음. `terraform output -json` 허용 목록 캐시(`platform.cloud.json`, 유상준이 씀)만 읽음(✅ 장부 27).
- [ ] `context.json`에 비밀값 없음. 로그의 계정 ID는 가림.
- [ ] `RunContext` 원문은 AI에 안 감. AI는 김준석의 가린 요약(키 이름·종류·개수·있음/없음)만 봄.

**부트스트랩 관리자 자격 (💭 N29, 유상준과)**
- [ ] 승인 때 받은 프로필에서 **단기 키 3개만** 꺼내 `apply_infra`의 terraform 자식 프로세스 env로. `AWS_PROFILE`·SSO 캐시 경로는 안 넘김.
- [ ] `HOME`은 빈 임시 디렉토리, env 허용 목록에 `TF_LOG` 없음.
- [ ] 상태 DB·이벤트·로그·AI 입력·다른 툴에 넣지 않음. apply가 끝나면 참조를 버림. 승인 기록에는 그 세션의 caller ARN만.

**승인 POST (💭 P0, 양서윤과)**
- [ ] `Host`·`Origin`이 `127.0.0.1:<포트>`(💭 8765)가 아니면 거부 + CSRF 토큰. 운영자 브라우저의 악성 페이지가 승인을 대신 누르는 것을 막음.

**실패 위치별 결과 (요약, 💭 세부 코드)**

| `schema`, `run_id`, `project`, `mode`(`update`/`bootstrap`) | 실행 모드 |
| `facts_hash`, `plan_hash` | V11·V12 |
| `toggles` | `{"code_patch": false}` 일반 실행 기본 OFF, 데모는 ON(✅ 9/30 오후, 장부 16 대체) |
| `build`, `deploy.local`, `deploy.cloud`, `verify` | 각각 `steps[]`·`skipped[]`. 순서 = 배열 순서 |
| step `id`·`tool`·`target`·`tier`·`params` | `tool`은 레지스트리 이름. `params`는 step별 허용 키만 |
| step `layer`·`effect`(`read`/`additive_prep`/`state_change`) | 롤백 대상 판단, W1 |
| step `wait_for`(항상 배열)·`signal` | 대기 지점 |
| step `run: "finally"` | verify 섹션에서만. `verify.report` |

- `plan.json`에는 도메인·IP·digest·ARN·비밀값이 없습니다. 있으면 검증 단계에서 거부됩니다(V3).

**`RunContext` = 환경 정보 스냅샷 (✅ 장부 27, 형식 💭 N38)**

| 원본 | 내용 | 읽는 방법 | 쓰는 사람 |
|---|---|---|---|
| ① Terraform 출력 | ALB·리스너 ARN, RDS 엔드포인트, 시크릿 ARN(앱·Docker Hub pull 토큰), ECS 클러스터·서비스, 역할 ARN | `platform.cloud.json`만(state 원문 금지). `apply_infra` 뒤 다시 읽음 | 유상준 |
| ② 관리 페이지 설정 | `cloud_domain`, `dns_mode`, `hosted_zone_id`, 토글 | 상태 DB `project_settings`를 run 시작 때 스냅샷 | 사람(양서윤 화면) |
| ③ 온프렘 인벤토리 | tier별 docker 주소, `db_host`, `was_upstream`, `.env` 경로, `public_url` | `platform.onprem.yaml` | 김준석 |
| ④ 실행기 DB | 배포 digest, 릴리스 목록, `env_release`, 마지막 인프라 요구 해시 | `var/ddak.sqlite` | 나(실행기) |

- 그 밖의 필드 💭: `run_id`, `project`, `mode`, `source_sha`, `snapshot_sha256`, 이미지 digest(manifest), 대상별 `previous_release`, 승인 기록 요약, apply 세션 종류, 어댑터 모드(real/fake), LLM backend 이름, `lock_token`, `deadline`.
- 저장: 메모리 객체 + `var/runs/<run_id>/context.json`(재생·디버깅용, 비밀값 없음).

**CD 공통 인터페이스 (✅ 장부 29, 함수·인자 💭)**

| 함수 | 부르는 툴 | onprem provider(나) | aws provider(안승환) |
|---|---|---|---|
| `deploy(tier, ctx)` | `deploy_tier` | tier 컨테이너를 digest로 재생성 | 새 리비전으로 `update_service` |
| `rollback(tier, ctx)` | `rollback_tier` | 이전 digest로 재생성 | 이전 태스크 정의 ARN으로 `update_service` |
| `health_check(ctx)` | `health_check` | `/health/ready` + `docker inspect` digest(장민영, index 소속 확인) | `/health/ready` + ECS `imageDigest`(양서윤, index 소속 확인) |

- `ProviderResult`: `provider`, `function`, `applicable`(기본 true), `changed`, `detail`(400자 이하, 비밀값·계정 ID·절대 경로 금지). 툴이 자기 출력 모델로 옮겨 담습니다.
- provider는 코드가 고릅니다(`select_provider(target, 어댑터 모드)`: fake 모드 → `FakeProvider`, local → onprem, cloud → aws). AI가 고르지 않습니다.
- 수행 불가 = `DdakToolError(ErrorCode, 메시지)`. 검사 불합격 = 정상 반환 + `passed=False`. 해당 없음 = 실패 아님.

**승인 기록 (C-19, 💭)**
- 필드: run_id, 종류(`patch` / `deploy` / `infra` / `dockerfile`(P1) / `foundation`), 대상 해시(패치 = 원본 스냅샷 해시·diff 해시·수정본 스냅샷 해시 / `plan_hash` / plan sha256 / Dockerfile sha256 / 기반 템플릿 sha256), 승인자, 시각, 결과(승인/거절), (부트스트랩) 관리자 세션 caller ARN.
- 한 화면·한 번 승인: 같은 approval_id로 묶고 종류별 기록을 따로 저장합니다. 내용이 바뀌면 그 종류는 재승인입니다. 이전 패치 기록은 프로젝트와 세 해시가 같고 승인이었을 때만 재사용합니다(배포·인프라는 재사용 없음).

**release manifest (C-08, 💭 주요 필드)**
- `schema: "ddak.release/v1"`, `release_id`, `run_id`, `project`, `mode`, `source`(원본·수정본 snapshot_sha256, patches, 참고용 base_sha·dirty), `image_index_digest`와 `platform_digests`(amd64·arm64), 대상별 실제 관측값(관측한 플랫폼 + 그 플랫폼의 digest).
- `images.<tier>`: `ref`(`docker.io/<조직>/<이미지>@sha256:…`), `tag`(표시용 `<tier>-<release_id>`), `rebuilt`, `from_release`, `dockerfile.source`(`app`/`generated`)·`sha256`.
- `schema_version`(from·to·파일 sha256), `config[]`(키, class, policy, 대상별 `ref`(비밀) 또는 `value`(평문)).
- `cloud`(태스크 정의 ARN), `infra`(inputs_hash, plan_sha256, 요약), `plan_hash`, `facts_hash`, `previous_release_id`(대상별), `created_at`, `sealed_at`.
- 빌드 뒤 만들고, config 참조를 붙인 뒤 봉인합니다. 봉인 뒤 불변. 비밀은 참조만.

**`MIGRATE_RESULT` (C-09, 장민영)**
- 러너: `python -m flaskr.migrate {precheck|up|verify} --json`. stdout 한 줄 JSON + exit code.
- 요약 필드 💭: `current`, `expected`, `applied[]`, `signature`, `fingerprint`. 러너가 MySQL `GET_LOCK('flaskr_migrate', 10)`으로 동시 실행을 막습니다.

**run·트랙·step 상태 (💭)**
- run: `CREATED → ANALYZED → PLANNED → VALIDATED → AWAITING_APPROVAL → APPROVED → BUILDING ∥ DEPLOYING → COMPARING → REPORTED → 최종`.
- 최종: `SUCCEEDED` / `FAILED_BEFORE_DEPLOY` / `FAILED_LOCAL` / `FAILED_CLOUD` / `PARITY_FAILED` / `NEEDS_HUMAN` / `CANCELLED`.
- 트랙: `PENDING → RUNNING ⇄ WAITING → VERIFIED → DONE`, 실패 `FAILED → ROLLING_BACK → ROLLED_BACK | ROLLBACK_FAILED`, 클라우드 `ABORTED_AT_GATE`.
- step: `pending` / `waiting` / `running` / `succeeded` / `failed` / `skipped` / `aborted`.

## 7. AI 사용 경계

| 구분 | 내용 |
|---|---|
| 내 영역에서 AI가 하는 것 | **없음.** 실행기·onprem provider·잠금·롤백·기록은 전부 결정적 코드입니다(✅ 장부 4-a·6). |
| 내게 오는 AI 결과 | AI 제안(step 선택, Terraform HCL, Dockerfile)은 검증과 사람 승인을 거쳐 `plan.json`·승인 기록이 된 뒤에만 옵니다. 실행기는 AI 출력을 직접 받지 않습니다. |
| AI가 하지 않는 것 | 툴 호출, 순서·대기 지점 결정, provider 선택, 롤백 결정, 승인, 값(IP·digest·ARN·도메인·SECRET_KEY) 생성 |

| 강제 방법 | 실행기·웹은 툴 모듈을 import하지 않고 레지스트리 이름으로만 호출(import 규칙 검사). `call_ai`는 현재 툴이 AI 허용 툴이 아니면 `AI_NOT_ALLOWED`. |
| 환경 정보 | `RunContext` 원문은 AI에 가지 않습니다. AI는 김준석이 만드는 가린 요약만 봅니다(✅ 장부 27). |

## 8. 알려진 함정과 주의

| # | 함정 | 대응 |
|---|---|---|
| 1 | `asyncio.wait_for`로 `asyncio.to_thread` 작업을 취소해도 **스레드 안의 docker·boto3 호출은 멈추지 않음** | 어댑터가 `ctx.deadline`을 지킴(docker SDK timeout, subprocess kill) |
| 2 | 타임아웃 뒤에는 실제 상태를 모름(요청이 이미 나갔을 수 있음) | 롤백은 현재 상태 조회 뒤 필요한 것만(멱등) |
| 3 | nginx는 upstream 이름을 시작 때 한 번만 해석 → was 재생성으로 IP가 바뀌면 502. 10/1 E2E에서 먼저 깨질 곳 | was를 고정 IP(`172.30.0.10`)로 재생성하거나 nginx `resolver`. `deploy_tier(was)`의 네트워크 설정에 반영 |
| 4 | MySQL 컨테이너 헬스체크를 소켓으로 하면 초기화 중에도 healthy | `mysqladmin ping -h 127.0.0.1`(TCP) |
| 5 | DooD bind mount 경로는 데몬 호스트 기준 | 비밀 파일은 도커 볼륨이나 대상 호스트 안에서 생성 |
| 6 | 원격 도커(`ssh://`)로 Docker Hub pull 할 때 인증 위치(원격 호스트의 `docker login` vs SDK `auth_config`) **확인 필요** | 리허설에서 확인(담당 정준우). 안 되면 컨테이너 모드로 임시 |
| 7 | `~/.docker/config.json`은 credential helper가 없으면 base64 = 사실상 평문 | 읽기 전용 토큰만 둠, 데모 뒤 폐기 |
| 8 | `.env`·컨테이너 env는 `docker inspect`로 보임 | 한계로 명시. 줄이려면 헬퍼가 볼륨 파일(0400)에 쓰고 앱이 `*_FILE`로 읽는 안(N4) |
| 9 | SECRET_KEY를 매번 새로 만들면 전원 로그아웃. 환경 간 같은 값이면 V21 차단 | 있으면 재사용, 환경별 따로 |
| 10 | 설정 롤백을 안 한다는 전제: 이전 앱(v1)이 새 `.env`(v2 키 포함)로 떠야 함 | **확인 필요**(장민영과). 기존 키 값을 바꾸는 배포는 이 전제를 깸 |
| 11 | MySQL DDL은 암묵 커밋. 마이그레이션이 중간에 실패하면 앞 문장이 남음 | 러너의 문장 단위 가드(장민영). 실행기는 DB를 되돌리지 않음 |
| 12 | 실행기 잠금은 각자 노트북의 SQLite라 **노트북끼리 공유되지 않음** | 실제 클라우드 대상 run은 한 번에 한 명. 통합 창 시작·끝을 팀 채널에 알림 |
| 13 | 부트스트랩 인프라 apply 실패를 템플릿의 상태 판정이 `FAILED_CLOUD`로 셈 | `FAILED_BEFORE_DEPLOY`(`INFRA_APPLY_FAILED`)로 고침(내 TODO) |
| 14 | v2 인프라 apply는 `state_change`라 실패하면 롤백이 불림. 그런데 서비스는 아직 v1 | 앱 롤백은 no-op이어야 함. Terraform은 되돌리지 않음 |
| 15 | 인프라 apply가 G1 뒤라 로컬이 실패하면 apply가 안 됨. 승인된 plan은 다음 run에서 stale일 수 있음 | 다음 run에서 다시 plan·승인(`apply_infra`가 stale 거부) |
| 16 | apply 뒤 환경 정보를 다시 안 읽으면 시크릿 값 쓰기·태스크 정의 등록이 새 ARN을 못 찾음 | B8: apply 직후 `RunContext` 갱신 |
| 17 | IAM 전파 지연으로 첫 태스크가 새 시크릿을 못 읽을 수 있음(`ResourceInitializationError`) | 실행기는 `state_change` 자동 재시도 안 함. 대기·재시도는 안승환·유상준과 리허설 실측 뒤 정함 |
| 18 | 멀티 아키텍처 인덱스 digest ≠ 플랫폼별 digest | amd64·arm64 공통 index. 각 환경의 실제 digest를 해당 플랫폼 하위 digest와 대조 |
| 19 | `/version`을 digest 근거로 쓰면 안 됨 | `docker inspect`(`Config.Image` + `RepoDigests`)로 확인 |
| 20 | 온프렘을 `SESSION_COOKIE_SECURE=true`로 두면 Safari·파이썬 스모크(`http.cookiejar`)에서 로그인 유지 실패 | 온프렘 `false`, ProxyFix `0/0`. 데모 브라우저는 Chrome |
| 21 | 소켓 프록시는 CONTAINERS+POST를 열면 privileged 컨테이너 생성이 그대로 통과 | 코드 정책(5절)이 진짜 방어선. 발표에서 한계를 먼저 말함 |
| 22 | Docker Hub 무료 플랜 pull 한도(베이스 이미지 pull 포함) | 리허설에서 pull 횟수 확인. 막히면 ECR 어댑터 전환(안승환 판단) |
| 23 | 개발 PC 온프렘 컨테이너 모드는 목업에 가까움 | 발표 문구: "자원 이슈로 컨테이너로 진행, 실제는 tier별 서버를 가정"(✅ 장부 10) |
